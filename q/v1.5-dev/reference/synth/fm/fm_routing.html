FM Routing

Overview

A patch chart draws an FM instrument as boxes and lines: which operator modulates which, which ones reach the output, and where the feedback loop sits. fm_routing is that chart as an expression.

Figure 1. The DX7’s algorithm 1: OP2 modulates OP1, OP6 through OP4 are a stack into OP3, and OP6 feeds back on itself. OP1 and OP3 modulate nothing, so they are the carriers and their sum is the output.

  • Blue operators modulate another. Green ones modulate nothing, so they sound: they are the carriers.

  • OP6, in orange, feeds back on itself.

  • The sum of the carriers is the output.

Operators are numbered from 1, as the charts number them, and op<N> names one. >> is "modulates", chaining to the right the way a stack is drawn, and | puts paths side by side, or names an operator that only sounds:

Expression The chart it draws

op<2> >> op<1>

2 modulates 1.

op<6> >> op<5> >> op<4> >> op<3>

A stack of four.

op<4> >> op<3> | op<5> >> op<3>

Two operators modulating one.

op<6> >> op<4> | op<6> >> op<5>

One modulating two.

op<2> >> op<1> | op<3>

And operator 3 by itself.
>> binds tighter than |, so a whole chart reads without parentheses, and a path is already a routing: .feedback(op<6>) closes it and yields one. 
using namespace q::fm_ops;
auto r = (op<2> >> op<1> | op<6> >> op<5> >> op<4> >> op<3>).feedback(op<6>);

Carriers are derived

Nothing declares which operators sound. An operator that modulates nothing is a carrier, which holds for every one of the DX7’s 32 algorithms and for any chart worth drawing. So the carrier set cannot fall out of step with the paths, and an operator that only sounds is named on its own to say it is one of the voice’s (| op<3> above).

Ordering

A modulator must have a higher number than what it modulates. That is what lets FM Algorithm run the operators in one pass from the last down to the first, with each one’s modulators already computed. valid() reports a routing that breaks the rule, or that names an operator outside its count, and it is constexpr, so a routing can be checked at compile time:

static_assert(r.valid());
A routing is for a number of operators, given by the highest one the expression mentions. fm_max_operators is the most a mask can hold, 16; a synth wanting more runs more voices.

Include

#include <q/synth/fm/fm_routing.hpp>
#include <q/synth/fm/dx7_routing.hpp>   // and the DX7's 32

Declaration

namespace fm_ops
{
   template <std::size_t N>
   constexpr fm_op op{N};
}

constexpr fm_path operator>>(fm_op from, fm_op to);
constexpr fm_path operator>>(fm_path path, fm_op to);
constexpr fm_path operator|(fm_path a, fm_path b);
constexpr fm_path operator|(fm_path path, fm_op op);
constexpr fm_path operator|(fm_op op, fm_path path);
constexpr fm_path operator|(fm_op a, fm_op b);

struct fm_path
{
   constexpr fm_routing    feedback(fm_op op) const;
   constexpr fm_routing    feedback(fm_op src, fm_op dst) const;
};

struct fm_routing
{
   using table = detail::fm_routing_table;
   using mask = table::mask;

   constexpr               fm_routing(std::size_t size = fm_max_operators);
   constexpr               fm_routing(fm_path const& path);

   constexpr fm_routing&   operator()(fm_path const& path);
   constexpr fm_routing&   feedback(fm_op op);
   constexpr fm_routing&   feedback(fm_op src, fm_op dst);

   constexpr mask          carriers() const;
   constexpr mask          modulators() const;
   constexpr std::size_t   size() const;
   constexpr bool          valid() const;

   constexpr table         get() const;
};

Expressions

Notation

r, a, b

Objects of type fm_routing.

p

An fm_path, the result of a routing expression.

n

Number of operators. A std::size_t.

i

An operator index from 0, as the masks are numbered.

Building

Expression Semantics

op<N>

Operator N, numbered from 1.

a >> b

a modulates b. Chains to the right.

a | b

Both paths, side by side.

p.feedback(op<N>)

A routing of p, operator N feeding back into its own modulation.

p.feedback(op<S>, op<D>)

Feedback from operator S into operator D.

fm_routing{n}

A routing for n operators, none of them modulating another, so all of them sound.

fm_routing{n}(p)

The paths of p, for n operators.

Queries

Expression Semantics

r.carriers()

Mask of the operators that sound.

r.modulators()

Mask of the operators that modulate another.

r.size()

How many operators the routing is for.

r.valid()

false if a path was misordered or named an operator the routing has not got.

r.get()

The low level table FM Algorithm reads.

The DX7’s 32 algorithms

dx7_routing[N - 1] is the DX7’s algorithm N, written as the chart draws it, with all six operators named in every row.

They are a useful set of six operator topologies whatever synth uses them, so they sit beside fm_routing rather than with the DX7’s own parameters. The chart’s op1 to op6 names stay in q::dx7; only the table itself is hoisted into q.

Example

A voice that uses a routing of its own, not the DX7’s:

using namespace q::fm_ops;

// Three operators: 3 and 2 both modulate 1, and 3 feeds back on itself.
// Operator 1 modulates nothing, so it is the one that sounds.
constexpr auto route =
   (op<3> >> op<1> | op<2> >> op<1>).feedback(op<3>);

static_assert(route.valid());       // ordered, and within its operators

q::basic_fm_voice<
   q::fm_operator, q::fm_operator, q::fm_operator
> voice{
{
   .algorithm = {
      route,
      4 * q::pi,   // index: radians at full modulation
      q::pi / 2    // feedback: radians at full output
   }},
   sps
};
