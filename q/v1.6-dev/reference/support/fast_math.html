Fast Math

Overview

Audio DSP calls transcendental functions constantly: an oscillator needs a sine every sample, a compressor converts to and from decibel (log10 / pow10) on every gain update, a soft clipper computes a tanh per sample. The standard-library versions are correctly rounded to the last bit, at a cost in cycles that a per-sample loop rarely needs to pay: the result is quantized, summed with noise and turned into sound. Q provides a family of fast approximations that trade a little accuracy for a large speed-up.

Every function comes in two tiers, distinguished by name:

  • fast_*: the accurate tier. The error is inaudible in almost any audio use (a few parts in 100,000 for the bounded functions). Use it by default.

  • faster_*: the cheap tier. It drops a polynomial term or two, so the error grows to the low percent range, in exchange for the fewest operations. Use it where the result feeds something forgiving, such as a modulation source or a rough envelope, and the cycles matter.

The approximations are IEEE-754 bit tricks and short polynomials, from Paul Mineiro’s fastapprox. They take and return float; there are no double overloads.

The error ripples as the input sweeps: each approximation runs slightly high, then slightly low, of the exact value. The worst-case sizes are tabulated in Accuracy and Speed.

The trigonometric functions do no range reduction. fast_sin and fast_cos require -pi <= x <= pi; fast_tan requires -pi/2 <= x <= pi/2. Outside those ranges the polynomial diverges. Reduce the angle first, for example with a phase accumulator, which wraps by construction.

Accuracy and Speed

Accuracy is the worst-case error over each function’s working domain: inaudible for the fast_* tier, coarse for faster_*. The figures below were measured with clang -O3 on an Apple-silicon Mac, scalar path; they shift with compiler, flags and target.

Speed depends on how the calls are arranged. Independent calls pipeline, and the CPU runs many at once (throughput); chained calls each wait for the last (latency). For these functions the two differ by up to an order of magnitude: the large savings are in throughput, and inside a dependency chain the pipeline latency dominates and the saving shrinks. The build-only micro-benchmarks under test/benchmark/ measure them on your own target.

In throughput fast_log10 is about 19 times cheaper than std::log10; in a dependency chain, about 1.4 times. log2_bench.cpp and sin_bench.cpp measure log2 and sin with a dependency-bound loop, nearer the latency column: std::sin runs about 12 ns against roughly 2 ns for both fast_sin and faster_sin, and std::log2 about 8 ns against 2.5 ns.

On a modern desktop FPU the faster_* tier is often no quicker than fast_*: both compile to a handful of instructions, and the dropped polynomial term is hidden by pipeline latency. faster_* pulls ahead on cheaper hardware, where every multiply counts, and under vectorization. fast_* is faster than the libc call on every target.

The logarithms require x > 0.
The exponentials clamp a large negative input: fast_exp, fast_pow2 and fast_pow10 return the smallest normal float (about 1.2e-38), and their faster_ counterparts a denormal just below it. A large positive input is not clamped: past about 88 for fast_exp, 38 for fast_pow10 and 128 for fast_pow2, and the same for their faster_ counterparts, the result is NaN or has the wrong sign.

Hyperbolic Tangent

Expression Semantics Return Type

fast_tanh(x)

Compute the hyperbolic tangent of x, with x clamped to +/-9.

float

faster_tanh(x)

Compute the hyperbolic tangent of x, with x clamped to +/-9, coarse.

float

fast_rational_tanh(x)

Compute the hyperbolic tangent of x (-3 <= x <= 3) by a Pade rational approximation.

float
In float, tanh is 1 from about 9 up, so the clamp in fast_tanh and faster_tanh changes no result; it keeps the underlying exp from overflowing. fast_rational_tanh does not saturate: past /-3` its result grows past `/-1.

Reciprocal, Division and Square Root

Expression Semantics Return Type

fast_inverse(x)

Compute an estimate of 1/x by negating the IEEE-754 exponent.

float

fast_div(a, b)

Compute an estimate of a/b, as a * fast_inverse(b).

float

fast_sqrt(x)

Compute the square root of x (x >= 0) with std::sqrt.

float
fast_inverse, and therefore fast_div, is within about 5% of the exact value. Use it for control-rate math where the imprecision washes out.
fast_sqrt is exact: std::sqrt compiles to a single hardware instruction on every target Q supports.

The Taylor series are accurate only for small x; a higher order widens the usable range. fast_rand is a linear congruential generator with a fixed seed, held in a function-local static shared by all callers.
fast_rational_tanh, fast_exp3 to fast_exp9 and log2_10 are constexpr. The other functions rely on runtime type punning and are inline only.

Example

Apply a soft clipper, with a drive in decibels, to the input samples in:

#include <q/support/base.hpp>
...
namespace q = cycfi::q;

float drive;                        // in decibels
...
auto gain = q::fast_pow10(drive / 20);     (1)
for (auto& s : in)
   s = q::fast_tanh(s * gain);             (2)
1 Convert the drive from decibels to a linear gain.
2 Saturate the amplified sample with the hyperbolic tangent.
