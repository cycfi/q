LPC Fit

This API is new and unstable: it may change in any release, without a deprecation, until it matures.

Overview

The LPC fit turns a spectral envelope into an all-pole model: a filter of a few poles, 32 by default, whose spectrum follows the spectral envelope. This is linear prediction (LPC). A spectral envelope of thousands of bins becomes a few numbers that a filter can apply at no latency: the reflection coefficients k that an EQ Matcher takes, and a level.

It takes the spectral envelope in dB on the bins of a spectrum, DC to Nyquist, as a Spectral Learner draws it. It returns the model’s prediction error e; the model’s spectral envelope is then e / |A(f)|^2, up to the spectrum’s scale, so sqrt(e) is the model’s level. response() gives |A(f)|^2, and polynomial() gives A(z) itself.

A higher order follows a spectral envelope more closely, and costs a filter that applies it more: 32 resolves a guitar’s pickup resonance and body; 24 is close, and a quarter cheaper.

The LPC fit is implemented by a class template named basic_lpc_fit, on how it computes |A(f)|^2; lpc_fit takes the default.

Include

#include <q/fft/lpc_fit.hpp>

Declaration

template <typename Response = /* lpc_clenshaw or lpc_fft */>
class basic_lpc_fit
{
public:

   using response_type = Response;

   explicit             basic_lpc_fit(
                           std::size_t bins
                         , std::size_t order = 32
                        );

   double               operator()(
                           std::span<float const> db
                         , std::span<float> k
                        );

   double               response(std::size_t bin) const;
   void                 response(std::span<float> mag2) const;
   std::span<double const> polynomial() const;
   std::size_t          bins() const;
   std::size_t          order() const;
};

Template Instantiations

lpc_fit is the template instantiation with the default response, chosen for the processor:

lpc_fit

basic_lpc_fit<lpc_fft> on a computer; basic_lpc_fit<lpc_clenshaw> on a microcontroller (an Arm Cortex-M), where memory is short and double arithmetic slow.

using lpc_fit = basic_lpc_fit<>;

Response Policies

Response computes |A(f)|^2 after each fit:

lpc_clenshaw

At each bin asked for, by Clenshaw’s recurrence, with no memory beyond the fit’s.

lpc_fft

At every bin at once, by one FFT after each fit, for a spectrum’s worth of memory and the FFT’s.

On the H723, a fit and a full response take 4.8 ms with lpc_clenshaw and 3.1 ms with lpc_fft; on the M2, 76 µs and 32 µs. See Performance.

lpc_fft

class lpc_fft
{
public:

                        lpc_fft(std::size_t bins, std::size_t order);

   void                 prepare(
                           std::span<double const> a
                         , std::span<float const> cos
                        );
   double               operator()(std::size_t bin) const;
};

A policy of one’s own has the same three members: it is constructed with the bins and the order, prepare is given A(z) and the cosine table cos(2 pi i / n), i from 0 to n - 1 (n the spectrum’s size), after each fit, and the function call gives |A(f)|^2 at a bin.

Example

Fit a learned spectral envelope, for an EQ Matcher to apply:

#include <q/fft/lpc_fit.hpp>
#include <q/fft/spectral_learner.hpp>    // For spectral_learner
#include <cmath>
#include <vector>
...
namespace q = cycfi::q;

extern q::spectral_learner learner;      // has heard the guitar
...
q::lpc_fit fit{learner.bins()};
std::vector<float> db(learner.bins()), k(fit.order());
float level;

// Off the audio thread
void model()
{
   learner.spectral_envelope(db);                            (1)
   level = float(std::sqrt(fit(db, k)));                     (2)
}
1 The learned spectral envelope, in dB at each bin.
2 Fit it: its model’s reflection coefficients into k, and its level.

Implementation Details

Implementation details are subject to change without notice. Rely only on the expressions above.

The spectral envelope’s power, transformed back, gives its autocorrelation at the first order + 1 lags, and the Levinson-Durbin recursion (q::levinson, in <q/utility/levinson.hpp>) gives the model. White noise 60 dB under the power keeps a model of a spectral envelope with deep notches well conditioned. The lags are summed one at a time, each in four interleaved sums over a cosine table, which suits both an in-order core (no memory traffic) and an out-of-order one (no single chain of dependent additions).

lpc_clenshaw sums |A(f)|^2 = c[0] + 2 sum c[l] cos(l w), c the autocorrelation of A’s coefficients, as a Chebyshev series in `cos(w) by Clenshaw’s recurrence, in double: in float, the levels a Formant Table derives from it move by up to 0.16 dB.

Performance

Measured at 48 kHz in blocks of 32 samples (0.67 ms), on an Apple M2 and on an STM32H723 at 550 MHz with caches on. Average: the time a sample, and its share of a sample period. Worst: the slowest block, and its share of the block’s 0.67 ms; over 100%, it runs late. Figures are rounded and vary with the build and the input.

With lpc_fft, the fit includes the FFT and the response only reads it. The fit allocates about 25 KB with lpc_clenshaw; lpc_fft adds about 15 KB with PFFFT, and about 40 KB with Q’s own FFT.
