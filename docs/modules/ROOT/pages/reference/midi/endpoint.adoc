= MIDI Endpoint

include::../../common.adoc[]

== Overview

IMPORTANT: Read {midi2_messages} and {midi_readers} first for prerequisite information.

A MIDI 2.0 connection begins with discovery. Before sending a note, a host requests the description of the other end: its name, its manufacturer, the protocol it supports, and the parts it is built from. The other end is a UMP endpoint, and its parts are function blocks, each a named set of groups with a direction. An endpoint that sends no reply is not a MIDI 2.0 endpoint as far as the host is concerned.

A sequencer, on connecting, requests a synth's description, learns that it takes MIDI 2.0 and has one function block, and from then on sends 32 bit controllers and per-note bend in place of seven bit control changes.

Q implements both sides. `endpoint_inquiry` sends the requests and gathers the replies, and `stream_responder` builds each reply from a description the device supplies and passes every other message along. The requests and the replies are stream messages, typed messages a processor receives. See {midi} for where these sit.

{midi_ci} is a separate, older protocol, carried in universal system exclusive rather than in stream messages. It reports what a device is capable of, where discovery here reports how a connection is arranged.

image::midi-endpoint-discovery.svg[alt="Discovery between a host and an endpoint", width=650px, align=center, title="Discovery. The host sends two requests, and each names the replies it selects.", link={imagesdir}/midi-endpoint-discovery.svg]

== Stream Messages

The stream messages live in `namespace midi_2_0`. A stream message is message type 0xF, four words, addressed to the endpoint rather than to a group or a channel. The first word carries the type, a two bit form saying whether the message is complete in this packet or spans several, and a ten bit status naming the message. `dispatch` passes each to a processor (see {midi_processor}), and `packet_reader` gathers the three that carry text into views (see {midi_readers}).

```c++
namespace stream_status
{
   enum
   {
      endpoint_discovery            = 0x00,
      endpoint_info                 = 0x01,
      device_identity               = 0x02,
      endpoint_name                 = 0x03,

      stream_configuration          = 0x06,
      function_block_discovery      = 0x10,

      function_block_name           = 0x12,
      start_of_clip                 = 0x20,
      end_of_clip                   = 0x21
   };

struct stream_message : packet_message\<4>
{
   using packet_message<4>::packet_message;

   constexpr std::uint8_t     form() const;
   constexpr std::uint16_t    status() const;
};

namespace protocol
{
   enum
   {
      midi1 = 0x01,
      midi2 = 0x02
   };
}

// What a Stream Configuration Request and a Stream Configuration share.
struct stream_configuration_message : stream_message
{
   using stream_message::stream_message;

   constexpr std::uint8_t     protocol() const;
   constexpr bool             receives_jr() const;

// What packet_reader gathers the three text messages into.
struct text_view : message_base
{
   constexpr text_view(std::string_view text);

   constexpr std::string_view text() const;
};
```

NOTE: Like a `sysex_view`, the text of a `text_view` refers to the reader's buffer and is valid only for the duration of the call.

== Describing an Endpoint

A device declares itself once, in an `endpoint_description`, and every reply is built from it.

=== Include

```c++
#include <q/midi/endpoint.hpp>
```

=== Declaration

```c++
namespace direction
{
   enum
   {
      input          = 0b01,
      output         = 0b10,
      bidirectional  = 0b11
   };
}

namespace ui_hint
{
   enum
   {
      unknown  = 0b00,
      receiver = 0b01,
      sender   = 0b10,
      both     = 0b11
   };
}

struct function_block
{
   bool              active;
   std::uint8_t      direction;        // direction::input, output, bidirectional
   std::uint8_t      midi1;            // 0 none, 1 yes, 2 yes at 31.25 kb/s
   std::uint8_t      ui_hint;          // ui_hint::unknown, receiver, sender, both
   std::uint8_t      first_group;
   std::uint8_t      groups;
   std::uint8_t      midi_ci_version;  // 0 for none
   std::uint8_t      sysex8_streams;
   std::string_view  name;             // UTF-8, at most 98 bytes
};

struct endpoint_description
{
   std::string_view  name;                 // at most 98 bytes
   std::string_view  product_instance_id;  // ASCII, at most 16
   midi_ci::identity identity;
   bool              midi2;                // protocols supported
   bool              midi1;
   bool              receives_jr;          // timestamps
   bool              transmits_jr;
   std::uint8_t      protocol;             // the one in use now
   bool              static_function_blocks;
   std::span<function_block const> blocks; // at most 32
};
```

=== Example

Describe an endpoint named "Q Endpoint" with one function block, "Keys":

```c++
#include <q/midi/endpoint.hpp>

namespace midi2 = cycfi::q::midi_2_0;

midi2::function_block const blocks[] =
{
   {true, midi2::direction::bidirectional, 0, midi2::ui_hint::both     <1>
    , 0, 1, 0x02, 0, "Keys"}
};

midi2::endpoint_description description{
   "Q Endpoint", "SN-001", {0x002109, 0x0102, 0x0304, 0x01020304}      <2>
 , true, true, false, false, midi2::protocol::midi2, true               <3>
 , std::span<midi2::function_block const>{blocks}};                     <4>
```

<1> An active block that receives and sends, has no MIDI 1.0 port, and serves as both receiver and sender. It covers one group, starting at group 0, and supports MIDI-CI version 0x02 with no 8 bit system exclusive streams.
<2> The name, the product instance id, and the identity: manufacturer, family, model and revision.
<3> MIDI 2.0 and MIDI 1.0 supported, no jitter reduction timestamps, MIDI 2.0 in use, and static function blocks.
<4> The function blocks.

== stream_responder

`stream_responder` is a processor proxy. It replies to the stream messages that call for a reply, sends the replies through `send`, and passes every other message to the next processor, so it sits between the reader and the synth like any other stage.

`stream_responder` refers to the description and holds no other state, so it can be built in each processing block with that block's `send`, as a plugin does. A granted Stream Configuration Request writes the new protocol into `endpoint_description::protocol`, so the protocol in use carries over from one responder to the next.

=== Include

```c++
#include <q/midi/endpoint.hpp>
```

=== Declaration

```c++
template <typename D, typename Send, typename P>
class stream_responder
{
public:

                           stream_responder(D& d, Send send, P next);

                           template <typename Message>
   void                    operator()(Message msg, std::size_t time);
   void                    operator()(endpoint_discovery msg, std::size_t time);
   void                    operator()(stream_configuration_request msg, std::size_t time);
   void                    operator()(function_block_discovery msg, std::size_t time);

   std::uint8_t            protocol() const;
};
```

`D` is `endpoint_description`, or a class with a member function `endpoint()` that returns an `endpoint_description&`. A processor may be that class, and then one object is both the synth and the endpoint.

=== Expressions

==== Notation

`d`         :: Object of type `D`.
`send`      :: A {midi_sink} over `packet`, or a callable taking a `packet const&`.
`proc`      :: Instance of a type that conforms to `Processor`.
`s`         :: Object of type `stream_responder`.
`msg`       :: Instance of a MIDI message.
`time`      :: Value of type `std::size_t`: a time stamp.

==== Constructors

[cols="1,1"]
|===
| Expression                            | Semantics

| `stream_responder(d, send, proc)`     | Construct a `stream_responder` that replies
                                          for `d` through `send`, in front of `proc`.
| `stream_responder(s)`                 | Copy construct from `stream_responder s`.
|===

NOTE: C++ brace initialization may also be used.

`stream_responder` is not assignable.

WARNING: `d` must outlive every `stream_responder` that refers to it, and must not be `const`: a granted Stream Configuration Request writes the protocol into it.

==== Function Call

[cols="1,1,1"]
|===
| Expression            | Semantics                                       | Return Type

| `s(msg, time)`        | Reply to `msg` if it is a request, or pass it
                          to `proc`.                                      | `void`
|===

The replies, by request:

Endpoint Discovery:: The replies its filter selects, in the order the bits are numbered: info, device identity, name, product instance id, stream configuration.

Stream Configuration Request:: A Stream Configuration with the protocol in use, after switching to the protocol requested if the endpoint supports it.

Function Block Discovery:: Info and name, for one block or for all of them.

==== Accessors

[cols="1,1,1"]
|===
| Expression            | Semantics                                       | Return Type

| `s.protocol()`        | Get the protocol in use, `d.protocol`.          | `std::uint8_t`
|===

==== Example

Put a responder in front of a synth, and read the packets that arrive through it:

```c++
#include <q/midi/endpoint.hpp>
#include <q/midi/packet_reader.hpp>
...
namespace midi2 = cycfi::q::midi_2_0;

struct my_synth : midi2::processor { ... };
my_synth synth;                                   // the client's synth
extern midi2::endpoint_description description;  // as in Describing an Endpoint
extern midi2::packet p;                           // from the connection
std::size_t time;
...
auto send = [](midi2::packet const& reply) { /* to the host */ };   <1>
midi2::stream_responder responder{description, send, synth};         <2>

midi2::packet_reader<> reader;
reader(p, time, responder);                                           <3>
```

<1> Send each reply packet to the host.
<2> Construct the responder in front of `synth`. It refers to `description`.
<3> Read the packet. The responder replies to the requests and passes every other message to `synth`.

== Replies

`stream_responder` builds its replies with these functions, and a device that replies without a `stream_responder` calls them directly.

=== Include

```c++
#include <q/midi/endpoint.hpp>
```

=== Declaration

```c++
constexpr packet make_endpoint_info(
   bool static_blocks, std::uint8_t blocks
 , bool midi2, bool midi1, bool receives_jr, bool transmits_jr);

constexpr packet make_device_identity(midi_ci::identity const& id);

constexpr packet make_stream_configuration(
   std::uint8_t protocol, bool receives_jr, bool transmits_jr);

constexpr packet make_function_block_info(
   std::uint8_t index, function_block const& fb);

template <typename Send>
void send_text(
   std::uint16_t status, std::string_view text, Send&& send
 , int block = -1);
```

Each `make_` function returns one packet. `send_text` sends a name or an id as the packets that carry it, through `send`, a {midi_sink} over `packet` or a callable taking a `packet const&`. `status` is `stream_status::endpoint_name`, `product_instance_id` or `function_block_name`, and `block` is the function block number for a function block name, -1 otherwise. A text longer than 98 bytes is cut to 98.

== endpoint_inquiry

`endpoint_inquiry` is the other side of `stream_responder`: it requests an endpoint's description and gathers the replies. It is a processor proxy, so the replies reach it the way any message does, and it passes every message along.

The replies arrive later as messages, on whatever thread the transport uses, or never, and nothing marks the end of them. The caller drives the inquiry with `poll` and keeps the time.

=== Include

```c++
#include <q/midi/inquiry.hpp>
```

=== Declaration

```c++
template <typename P, std::size_t MaxBlocks = 32>
class endpoint_inquiry
{
public:

   static constexpr std::size_t max_blocks = MaxBlocks;
   static constexpr std::size_t max_name = 98;
   static constexpr std::size_t max_id = 16;

   explicit                endpoint_inquiry(P next);

                           template <typename Send>
   void                    poll(Send&& send, std::size_t time);

                           template <typename Message>
   void                    operator()(Message msg, std::size_t time);
   void                    operator()(endpoint_info msg, std::size_t time);
   void                    operator()(device_identity msg, std::size_t time);
   void                    operator()(endpoint_name_view msg, std::size_t time);
   void                    operator()(product_instance_id_view msg, std::size_t time);
   void                    operator()(stream_configuration msg, std::size_t time);
   void                    operator()(function_block_info msg, std::size_t time);
   void                    operator()(function_block_name_view msg, std::size_t time);

   bool                    started() const;
   bool                    complete() const;
   std::size_t             started_at() const;
   endpoint_description    description() const;
   void                    restart();
};
```

=== Expressions

==== Notation

`I`         :: An `endpoint_inquiry<P, MaxBlocks>` type.
`inq`       :: Object of type `I`.
`proc`      :: Instance of a type that conforms to `Processor`.
`send`      :: A {midi_sink} over `packet`, or a callable taking a `packet const&`.
`msg`       :: Instance of a MIDI message.
`time`      :: Value of type `std::size_t`: a time stamp.

==== Constructor

[cols="1,1"]
|===
| Expression                    | Semantics

| `endpoint_inquiry(proc)`      | Construct an `endpoint_inquiry` in front of `proc`,
                                  with no request sent.
|===

NOTE: C++ brace initialization may also be used.

`endpoint_inquiry` is not copyable: the description it returns refers to storage inside it.

==== Function Call

[cols="1,1,1"]
|===
| Expression                | Semantics                                     | Return Type

| `inq(msg, time)`          | Record `msg` if it is a reply, and pass it
                              to `proc`.                                    | `void`
|===

==== Operation

[cols="1,1,1"]
|===
| Expression                | Semantics                                     | Return Type

| `inq.poll(send, time)`    | Send the next request through `send`, if
                              one is due.                                   | `void`
| `inq.restart()`           | Reset the inquiry and discard the
                              description gathered.                         | `void`
|===

NOTE: `poll` acts only when the inquiry can move on, so it is safe to call at any rate. It sends two requests in turn, because the number of function blocks is in the reply to the first.

NOTE: Nothing times out. `started_at()` returns the time passed to the first `poll`. Compare it with the current time to decide when to stop waiting, and call `restart` to begin again.

==== Access

[cols="1,1,1"]
|===
| Expression                | Semantics                                     | Return Type

| `I::max_blocks`           | Get the most function blocks the inquiry
                              holds, `MaxBlocks`.                           | `std::size_t`
| `I::max_name`             | Get the longest name the inquiry holds,
                              98 bytes.                                     | `std::size_t`
| `I::max_id`               | Get the longest product instance id the
                              inquiry holds, 16 bytes.                      | `std::size_t`
|===

==== Accessors

[cols="1,1,1"]
|===
| Expression                | Semantics                                     | Return Type

| `inq.started()`           | Get whether the first request has been sent.  | `bool`
| `inq.complete()`          | Get whether every reply has arrived.          | `bool`
| `inq.started_at()`        | Get the time passed to the first `poll`.      | `std::size_t`
| `inq.description()`       | Get the description gathered from the
                              replies.                                      | `endpoint_description`
|===

WARNING: The description refers to storage inside the inquiry, so it is good only while the inquiry lives and until `restart`. `MaxBlocks` bounds that storage, and 32 is the most function blocks an endpoint may have.

==== Example

Request the description of the endpoint at the other end of a connection, for a host:

```c++
#include <q/midi/inquiry.hpp>
#include <q/midi/packet_reader.hpp>
#include <iostream>
...
namespace midi2 = cycfi::q::midi_2_0;

struct my_host : midi2::processor { ... };
my_host host;                                     // the host's processor
void send(midi2::packet const& request);          // to the endpoint
extern midi2::packet p;                           // from the connection
std::size_t time;
...
midi2::endpoint_inquiry inquiry{host};                      <1>
midi2::packet_reader<> reader;

inquiry.poll(send, time);                                   <2>
reader(p, time, inquiry);                                   <3>

if (inquiry.complete())
   std::cout << inquiry.description().name << std::endl;    <4>
```

<1> Construct the inquiry in front of `host`.
<2> Send the next request, if one is due. Call this as often as convenient, in a loop that already exists.
<3> Read the packet. The inquiry records the replies and passes every message to `host`.
<4> Once every reply has arrived, print the endpoint's name.

== Requests

`endpoint_inquiry` sends these requests, and a host that requests without an `endpoint_inquiry` builds them with these functions.

=== Include

```c++
#include <q/midi/inquiry.hpp>
```

=== Declaration

```c++
namespace discovery_filter
{
   enum
   {
      info                 = 0x01,
      device_identity      = 0x02,
      name                 = 0x04,
      product_instance_id  = 0x08,
      stream_configuration = 0x10,
      all                  = 0x1F
   };
}

namespace block_filter
{
   enum
   {
      info = 0x1,
      name = 0x2,
      all  = 0x3
   };
}

constexpr packet make_endpoint_discovery(
   std::uint8_t filter = discovery_filter::all);

constexpr packet make_function_block_discovery(
   std::uint8_t block, std::uint8_t filter = block_filter::all);
```

`discovery_filter` names the five replies an endpoint discovery can select, and `block_filter` the two a function block discovery can. A block number of `function_block_discovery::all` covers every block.

See {midi_ci} for `midi_ci::make_discovery`, which builds the message that begins a MIDI-CI exchange.
