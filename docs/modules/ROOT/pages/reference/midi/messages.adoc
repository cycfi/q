= MIDI 1.0 Messages

include::../../common.adoc[]

== Overview

MIDI is one way to control DSP parameters in a more meaningful, and musical way. Here, we talk about MIDI as a standardized messaging protocol. MIDI messages include note-on and note-off messages, control change messages, program change messages, and pitch bend messages, as well as tempo, time signature, and other performance data.

The MIDI 1.0 messages are small value types that hold the bytes of a message and read its fields through accessors. A {midi_processor} receives them. See {midi2_messages} for their MIDI 2.0 counterparts, and {midi} for how the messages, the processors and the rest of Q's MIDI fit together.

== Include

```c++
#include <q/midi/messages.hpp>   // the MIDI 1.0 messages, and the two below
#include <q/midi/cc.hpp>         // the controller numbers, on their own
#include <q/midi/note.hpp>       // the note helpers, on their own
```

== Namespaces

```c++
namespace cycfi::q::midi     { /**...**/ }   // what both protocols share
namespace cycfi::q::midi_1_0 { /**...**/ }   // MIDI 1.0
```

The MIDI 1.0 messages live in `namespace midi_1_0`, and the MIDI 2.0 messages in `namespace midi_2_0`, where a message of the same name means the same thing at a higher resolution. `namespace midi` holds what both protocols share: `message_base`, the controller numbers in `cc`, the note helpers, and the nine system messages, which MIDI 2.0 carries unchanged. `midi_1_0` names all of these too, so `midi_1_0::cc::sustain` and `midi::cc::sustain` are the same thing. See {midi_cc} and {midi_notes}.

== Generic MIDI Messages

The MIDI 1.0 message is basically an array of `std::uint8_t` with sizes 1 to 3, encapsulated in a `struct`. A whole MIDI 1.0 message as bytes, system exclusive included, travels as a {byte_span}, which the readers of {midi_readers} take and a MIDI 1.0 {midi_sink} sends.

```c++
using byte_span = std::span<std::uint8_t const>;   // namespace cycfi::q
```

The message structs:

```c++
struct message_base {}; // Base class for all messages

template <int size_>
struct message : message_base
{
   static constexpr int const size = size_;
   std::uint8_t data[size];
};

struct message1 : message\<1>
{
   message1() = default;
   constexpr message1(raw_message msg);
};

struct message2 : message\<2>
{
   message2() = default;
   constexpr message2(raw_message msg);
};

struct message3 : message\<3>
{
   message3() = default;
   constexpr message3(raw_message msg);
};
```

== Raw MIDI Messages

Generic MIDI messages are constructed from `raw_message`, which is essentially a `std::uint32_t` encapsulated in a `struct` that holds the 24-bit MIDI 1.0 message, encoded as little-endian:

image::raw-midi-message.svg[alt="The four bytes of a raw MIDI message", width=720px, align=center, title="A raw MIDI message", link={imagesdir}/raw-midi-message.svg]

[cols="1,3"]
|===
| In the figure | What it is

| data          | The `std::uint32_t` the message is held in.
| unused        | Bits 31 to 24. A MIDI 1.0 message is three bytes at most.
| data 2        | The second data byte, where the message has one. Zero otherwise.
| data 1        | The first data byte, where the message has one. Zero otherwise.
| status        | The status byte: the message type and the channel.
|===

```c++
struct raw_message
{
   std::uint32_t data;
};
```

=== MIDI Status

The status byte indicates the type of MIDI message and includes both a status nibble (upper 4 bits) and a 16-channel number nibble (lower 4 bits).

image::midi-status.svg[alt="The two nibbles of a status byte", width=720px, align=center, title="A status byte", link={imagesdir}/midi-status.svg]

[cols="1,3"]
|===
| In the figure | What it is

| status        | Bits 7 to 4. Which message this is: a note on, a control change, a system message.
| channel       | Bits 3 to 0. Which of the sixteen channels it is for. A system message has no channel, and its status byte is whole.
|===

Here is the MIDI status enumeration:

```c++
namespace status
{
   enum
   {
      note_off         = 0x80,
      note_on          = 0x90,
      poly_pressure    = 0xA0,
      control_change   = 0xB0,
      program_change   = 0xC0,
      channel_pressure = 0xD0,
      pitch_bend       = 0xE0,
      sysex            = 0xF0,
      song_position    = 0xF2,
      song_select      = 0xF3,
      tune_request     = 0xF6,
      sysex_end        = 0xF7,
      timing_tick      = 0xF8,
      start            = 0xFA,
      continue_        = 0xFB,
      stop             = 0xFC,
      active_sensing   = 0xFE,
      reset            = 0xFF
   };
}
```

== Specific MIDI Messages

Specific MIDI messages are subclasses of the generic MIDI messages above.

=== note_off

```c++
struct note_off : message3
{
   using message3::message3;

   constexpr note_off(std::uint8_t channel, std::uint8_t key, std::uint8_t velocity);

   constexpr std::uint8_t     channel() const;
   constexpr std::uint8_t     key() const;
   constexpr std::uint8_t     velocity() const;
};
```

=== note_on
```c++
struct note_on : message3
{
   using message3::message3;

   constexpr note_on(std::uint8_t channel, std::uint8_t key, std::uint8_t velocity);

   constexpr std::uint8_t     channel() const;
   constexpr std::uint8_t     key() const;
   constexpr std::uint8_t     velocity() const;
};
```

NOTE: In MIDI 1.0, a `note_on` with a velocity of 0 is a note-off, and many instruments send one in place of a `note_off`. `dispatch` delivers it as a `note_on`, so a processor checks the velocity.

=== pitch_bend
```c++
struct pitch_bend : message3
{
   using message3::message3;

   constexpr pitch_bend(std::uint8_t channel, std::uint16_t value);
   constexpr pitch_bend(std::uint8_t channel, std::uint16_t lsb, std::uint8_t msb);

   constexpr std::uint8_t     channel() const;
   constexpr std::uint16_t    value() const;
};
```

The value is 14 bits, 0 to 16383, and the wheel at rest is 8192. The message carries the wheel position; how far full travel bends is the instrument's bend range.

=== sysex

```c++
template <int size_>
struct sysex : message<size_ + 5>
{
   constexpr sysex(std::uint16_t id, std::uint8_t const* data_in);

   constexpr std::uint16_t    id() const;
};
```

`sysex` is a system exclusive message to send, the one message with no fixed length, so it carries its own markers: 0xF0, the manufacturer's identifier, `size_` bytes of payload, then 0xF7. The identifier is written in its three byte form, a zero followed by the two halves of `id`. The identifier and payload bytes are masked to seven bits, since the eighth marks a status byte and would end the message early.

NOTE: `sysex` builds a message to send. A system exclusive message that arrives is gathered by `byte_reader`, which hands over a `sysex_view` of it. See {midi_readers}.

== Example

Hold the notes a pianist releases while the sustain pedal is down, and release them when the pedal lifts.

```c++
#include <q/midi/processor.hpp>
#include <bitset>
...
namespace midi = cycfi::q::midi_1_0;

struct my_voice
{
   void on(std::uint8_t velocity);
   void off();
};

my_voice& voice(std::uint8_t key);      // the voice that plays a key
...
struct sustaining_synth : midi::processor
{
   using midi::processor::operator();

   void operator()(midi::note_on msg, std::size_t time)
   {
      if (msg.velocity() == 0)                                       <1>
         (*this)(midi::note_off{msg.channel(), msg.key(), 0}, time);
      else
         voice(msg.key()).on(msg.velocity());
   }

   void operator()(midi::note_off msg, std::size_t)
   {
      if (_pedal)
         _held.set(msg.key());                                       <2>
      else
         voice(msg.key()).off();
   }

   void operator()(midi::control_change msg, std::size_t)
   {
      if (msg.controller() != midi::cc::sustain)                     <3>
         return;
      _pedal = msg.value() >= 64;
      if (!_pedal)
      {
         for (std::size_t key = 0; key != 128; ++key)                <4>
            if (_held.test(key))
               voice(key).off();
         _held.reset();
      }
   }

   bool              _pedal = false;
   std::bitset<128>  _held;
};
```

<1> Treat a `note_on` with a velocity of 0 as a `note_off`.
<2> Hold the released key while the pedal is down.
<3> Act on the sustain pedal, controller 64, only. The pedal is down from a value of 64 upward.
<4> When the pedal lifts, release every held key.
