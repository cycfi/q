= MIDI Messages

include::../../common.adoc[]

== Overview

MIDI is one way to control DSP parameters in a more meaningful, and musical way. Here, we talk about MIDI as a standardized messaging protocol. MIDI messages include note-on and note-off messages, control change messages, program change messages, and pitch bend messages, as well as tempo, time signature, and other performance data.

This page covers the MIDI 1.0 messages: each one a small value type that holds the bytes of the message and reads its fields through accessors. They are what a {midi_processor} receives. See {midi} for how the messages, the processors and the rest of Q's MIDI fit together, MIDI 2.0 included.


== Namespace

```c++
namespace cycfi::q::midi_1_0 { /**...**/ }
```

The MIDI 1.0 messages live in `namespace midi_1_0`. The MIDI 2.0 messages have a namespace of their own, `midi_2_0`, where a message of the same name means the same thing at a higher resolution.

== Generic MIDI Messages

The MIDI 1.0 message is basically an array of `std::uint8_t` with sizes 1 to 3, encapsulated in a `struct`:

```c++
struct message_base {}; // Base class for all messages

template <int size_>
struct message : message_base
{
   static constexpr int const size = size_;
   std::uint8_t data[size];
};

struct message1 : message\<1>
{
   message1() = default;
   constexpr message1(raw_message msg);
};

struct message2 : message\<2>
{
   message2() = default;
   constexpr message2(raw_message msg);
};

struct message3 : message\<3>
{
   message3() = default;
   constexpr message3(raw_message msg);
};
```

== Raw MIDI Messages

Generic MIDI messages are constructed from `raw_message`, which is essentially a `std::uint32_t` encapsulated in a `struct` that holds the 24-bits MIDI 1.0 message, encoded as little-endian:

image::raw-midi-message.svg[alt="Raw MIDI Message", width=500px, align=center, title="Raw MIDI Message", width=550]

```c++
struct raw_message
{
   std::uint32_t data;
};
```

=== MIDI Status

The status byte indicates the type of MIDI message and includes both a status nibble (upper 4 bits) and a 16-channel number nibble (lower 4 bits).

image::midi-status.svg[alt="MIDI Status Byte", width=500px, align=center, title="MIDI Status Byte", width=350]

Here is the MIDI status enumeration:

```c++
namespace status
{
   enum
   {
      note_off             = 0x80,
      note_on              = 0x90,
      poly_aftertouch      = 0xA0,
      control_change       = 0xB0,
      program_change       = 0xC0,
      channel_aftertouch   = 0xD0,
      pitch_bend           = 0xE0,
      sysex                = 0xF0,
      song_position        = 0xF2,
      song_select          = 0xF3,
      tune_request         = 0xF6,
      sysex_end            = 0xF7,
      timing_tick          = 0xF8,
      start                = 0xFA,
      continue_            = 0xFB,
      stop                 = 0xFC,
      active_sensing       = 0xFE,
      reset                = 0xFF
   };
}
```

=== pitch_bend
```c++

   constexpr pitch_bend(std::uint8_t channel, std::uint16_t value);
```

=== sysex

```c++
template <int size_>
struct sysex : message<size_ + 5>
{
   constexpr sysex(std::uint16_t id, std::uint8_t const* data_in);

   constexpr std::uint16_t    id() const;
};
```

`sysex` is a system exclusive message to send, the one message with no fixed length, so it carries its own markers: 0xF0, the manufacturer's identifier, `size_` bytes of payload, then 0xF7. The identifier is written in its three byte form, a zero followed by the two halves of `id`. Payload bytes are masked to seven bits, since the eighth marks a status byte and would end the message early.

NOTE: `sysex` builds a message to send. A system exclusive message that arrives is gathered by `byte_reader`, which hands over a `sysex_view` of it.

== Note Frequency

`note_frequency` converts a MIDI note number to its frequency in equal temperament, with A4, note 69, at 440 Hz.

```c++
constexpr frequency note_frequency(std::uint8_t key);
```

Example:

```c++
auto f = note_frequency(69); // 440_Hz
```

NOTE: The function covers notes 9 to 119, A-1 to B8, and returns a frequency of 0 outside them.

== Note

`note` names the MIDI note numbers from `C0`, 12, to `G9`, 127. A sharp is written with an `s` and a flat with a `b`, and the two names of one key are the same value: `note::Cs4` and `note::Db4` are both 61.

```c++
enum class note : std::uint8_t
{
   C0 = 12, Cs0, Db0 = Cs0, D0, /**...**/ G9
};
```

Example:

```c++
auto key = std::uint8_t(note::A4); // 69
```

== Note Name

The  `note_name` utility function can be used to convert a MIDI note number to a string representing the key.

```c++
constexpr char const* note_name(std::uint8_t key);
```

Example:

```c++
std::cout << note_name(60) << std::endl; // Prints "C4"
```

== Note Number

Conversely, the `note_number` utility function can be used to convert a string representing the key to a MIDI note number.

```c++
int note_number(std::string_view note)
```

The syntax is as follows:

1. A letter `a`-`g` or `A`-`G`
2. Optionally followed by `#` or `b`
3. Followed by the octave, `-1` to `9`

The range is from `C-1`, 0, to `G9`, 127, the whole of MIDI, so every name `note_name` gives reads back as the number it came from.

Example:

```c++
std::cout << note_number("C4") << std::endl; // Prints 60
```

NOTE: The function returns -1 when given invalid input, or a key that is not a MIDI note, such as `A9`.

== In MIDI 2.0

The controller numbers and the note numbers are the same in both protocols: MIDI 2.0 widened the values, not the meanings. `cc` and `note_frequency` are therefore named in `namespace midi_2_0` as well, so a MIDI 2.0 processor needs no MIDI 1.0 alias of its own:

```c++
namespace midi = cycfi::q::midi_2_0;

if (msg.controller() == midi::cc::sustain)
   /**...**/;
```
