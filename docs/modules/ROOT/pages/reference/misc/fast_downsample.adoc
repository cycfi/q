= Fast Downsample

include::../../common.adoc[]

== Overview

`fast_downsample_3` and `fast_downsample_5` halve a signal's sample rate with a useful amount of antialiasing, at almost no cost. Each takes two consecutive input samples per call and returns a single output, convolving the stream with a short binomial kernel as it decimates. These are deliberately cheap filters, not brick walls: they trade a gentle rolloff and some residual aliasing just below the new Nyquist for a handful of shifts and adds per output sample. Where transparent downsampling matters, use a steeper decimator; where a quick, light-touch rate halving is enough (roughing a signal down for a slower analysis path, for instance), these are hard to beat on cost.

Both kernels are repeated two-sample averages, so both are multiplierless and both place a null exactly at the old Nyquist frequency, where aliasing would be worst. They differ only in how many rounds of averaging are applied, which sets the steepness of the rolloff and the group delay.

The element type `T` is a template parameter, so the filters work with native integer or floating point samples (for example `uint16_t` or `float`). Both call operators are `constexpr`.

NOTE: `fast_downsample` is the original name of `fast_downsample_3`, from before there was more than one of them. It is retained as an alias, so existing code keeps compiling unchanged.

=== fast_downsample_3

`fast_downsample_3` convolves the stream with the three-tap kernel `{ 0.25, 0.5, 0.25 }`, giving

```
y(k) = (x(2k-1) + 2x(2k) + x(2k+1)) / 4
```

image::fast_downsample.svg[alt="The magnitude response of the { 0.25, 0.5, 0.25 } antialiasing kernel", width=700px, align=center, title="The pre-filter response, |H(f)| = cos^2(pi f / fs). It is down 6 dB (0.5) at the new Nyquist fs/4 and falls to a full null at the old Nyquist fs/2, where aliasing would be worst.", link={imagesdir}/fast_downsample.svg]

The kernel places a null exactly at the old Nyquist frequency, so the components most prone to aliasing are suppressed hardest, while content near the new Nyquist (`fs/4`) is attenuated by 6 dB. The filter carries one input sample of group delay and needs one sample of state.

=== fast_downsample_5

`fast_downsample_5` carries the same two-sample averaging one round further, giving the five-tap binomial kernel `{ 1, 4, 6, 4, 1 } / 16`:

```
y(k) = (x(2k-3) + 4x(2k-2) + 6x(2k-1) + 4x(2k) + x(2k+1)) / 16
```

It is still multiplierless, since 4x is a shift and 6x is a shift plus a shift. Because both kernels are repeated two-sample averages, the response of the five-tap filter is exactly the response of the three-tap one squared:

```
|H(w)| = cos^2(w/2)   for fast_downsample_3
|H(w)| = cos^4(w/2)   for fast_downsample_5
```

image::fast_downsample_5.svg[alt="The magnitude responses of the two kernels compared, in dB", width=700px, align=center, title="Squaring the response doubles the attenuation in dB everywhere. At the new Nyquist fs/4 that is 6 dB against 12 dB; by 0.40 fs it is 20.4 dB against 40.8 dB.", link={imagesdir}/fast_downsample_5.svg]

The price is one more input sample of group delay (two instead of one) and three samples of state instead of one. Three is the theoretical minimum here, since a five-tap window at stride two overlaps itself by `5-2 = 3`.

Binomial kernels are monotonic, so there is no passband ripple to compound when several of these are cascaded to reach a larger decimation factor. That is the main reason to prefer `fast_downsample_5` over an equal-length equiripple halfband, which is sharper on its own but fares worse in a cascade.

CAUTION: The weighted sum in `fast_downsample_5` reaches 16 times the input magnitude before the divide. An integral `T` that the usual arithmetic conversions do not promote to something wider (that is, a `T` at least as wide as `int`) needs four bits of headroom. Narrower integer types promote to `int` and are unaffected.

== Include

```c++
#include <q/fx/fast_downsample.hpp>
```

== Declaration

```c++
template <typename T>
struct fast_downsample_3
{
   constexpr T    operator()(T s1, T s2);

   T              x;    // filter state (defaults to 0)
};

// Retained for backward compatibility
template <typename T>
using fast_downsample = fast_downsample_3<T>;

template <typename T>
struct fast_downsample_5
{
   constexpr T    operator()(T s1, T s2);

   T              x0, x1, x2;    // filter state (defaults to 0)
};
```

== Expressions

In addition to the expressions below, `fast_downsample_3` and `fast_downsample_5` are default constructible and copy constructible.

=== Notation

`T`         :: Element type, e.g. `float` or `uint16_t`.
`DS`        :: A downsampler type, `fast_downsample_3` or `fast_downsample_5`.
`ds`        :: Object of type `DS<T>`.
`s1`, `s2`  :: A consecutive pair of input samples of type `T`.

=== Type Construction

[cols="1,1"]
|===
| Expression             | Semantics

| `DS<T>`                | Instantiate a downsampler type given the element
                           type `T`, e.g. `float`.
|===

=== Function Call

[cols="1,1,1"]
|===
| Expression     | Semantics                                        | Return Type

| `ds(s1, s2)`   | Filter and decimate the consecutive input pair
                   `s1`, `s2` into one output sample at half the rate. | `T`
|===

NOTE: Each call consumes two input samples and produces one output, so the output stream runs at half the input rate. Feed the input in consecutive pairs.

== Example

```c++
// Halve the sample rate of a stream, two input samples at a time
q::fast_downsample_3<float> ds;

// ... given a source that yields consecutive samples s1, s2:
float out = ds(s1, s2);   // one output sample at fs/2
```

Cascade the filters to decimate by a larger power of two. Four stages of `fast_downsample_5` give a decimation factor of 16:

```c++
q::fast_downsample_5<float> ds1, ds2, ds3, ds4;

// ... given 16 consecutive input samples in s[0..15]:
float a[8], b[4], c[2], out;
for (int i = 0; i != 8; ++i)
   a[i] = ds1(s[i*2], s[i*2+1]);
for (int i = 0; i != 4; ++i)
   b[i] = ds2(a[i*2], a[i*2+1]);
for (int i = 0; i != 2; ++i)
   c[i] = ds3(b[i*2], b[i*2+1]);
out = ds4(c[0], c[1]);      // one output sample at fs/16
```
