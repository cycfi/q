= Fast Downsample

include::../../common.adoc[]

== Overview

`basic_fast_downsample` halves a signal's sample rate with a useful amount of antialiasing, at almost no cost. It takes two consecutive input samples per call and returns a single output, convolving the stream with a short binomial kernel as it decimates. It is a cheap filter: it trades a gentle rolloff and some residual aliasing just below the new Nyquist for a handful of shifts and adds per output sample. Where transparent downsampling matters, use a steeper decimator; where a light rate halving is enough (roughing a signal down for a slower analysis path, for instance), this costs least.

The kernel is row `N-1` of Pascal's triangle over `2^(N-1)`, where `N` is the tap count. That single parameter fixes everything else:

[cols="1,3"]
|===
| kernel        | row `N-1` of Pascal's triangle, over `2^(N-1)`
| `\|H(w)\|`      | `cos^(N-1)(w/2)`
| group delay   | `(N-1)/2` input samples
| state         | `N-2` samples, the theoretical minimum, since an `N`-tap window at stride 2 overlaps itself by `N-2`
| DC gain       | 1.0, exactly, for every `N`
|===

image::fast_downsample.svg[alt="The magnitude response of the { 0.25, 0.5, 0.25 } antialiasing kernel", width=700px, align=center, title="The shape of the rolloff, on a linear scale, for N=3: |H(f)| = cos^2(pi f / fs). Every width is this same curve raised to a power, so every width shares the full null at the old Nyquist fs/2, where aliasing would be worst.", link={imagesdir}/fast_downsample.svg]

Because every kernel is a repeated two-sample average, all of them are multiplierless (the weights are shifts and adds) and none has passband ripple. Four widths have named aliases:

[cols="1,1,1,1,1"]
|===
| | `fast_downsample_2` | `fast_downsample_3` | `fast_downsample_4` | `fast_downsample_5`

| kernel       | `{ 1, 1 } / 2` | `{ 1, 2, 1 } / 4` | `{ 1, 3, 3, 1 } / 8` | `{ 1, 4, 6, 4, 1 } / 16`
| at `fs/4`    | -3.0 dB        | -6.0 dB           | -9.0 dB              | -12.0 dB
| at `0.40 fs` | -10.2 dB       | -20.4 dB          | -30.6 dB             | -40.8 dB
| group delay  | 0.5 sample     | 1 sample          | 1.5 samples          | 2 samples
| state        | none           | 1 sample          | 2 samples            | 3 samples
|===

image::fast_downsample_compare.svg[alt="The magnitude responses of the four named kernels compared, in dB", width=700px, align=center, title="The four responses in dB. Each extra round of averaging adds the same amount of attenuation again in dB, since these are one rolloff raised to the powers 1 through 4.", link={imagesdir}/fast_downsample_compare.svg]

`fast_downsample_2` needs no state at all: its window is exactly the pair of samples it is handed. Every kernel places a null at the old Nyquist frequency, so the components most prone to aliasing are suppressed hardest, while content near the new Nyquist (`fs/4`) is attenuated by 3 dB per round of averaging.

Being even in length, `fast_downsample_4` centers its window half a sample between input samples, so its group delay is a half-integer. A cascade that mixes it with the odd-length widths carries a half-sample offset at that stage's rate.

== Cascading

Cascade these to decimate by a larger power of two. Because every kernel is a repeated two-sample average, `n` cascaded stages collapse exactly to a CIC decimator of rate `R = 2^n` and order `N-1`:

```
prod(k = 0..n-1) (1 + z^-2^k) = 1 + z^-1 + ... + z^-(2^n - 1)
```

So four stages of `fast_downsample_5` are exactly a CIC `N=4 R=16`, factored as short FIRs running at successively lower rates, where a CIC uses Hogenauer's integrator-comb form. The factorization costs somewhat more adds. Every stage has bounded state, so it needs none of the integer-only modular arithmetic that a CIC's unbounded integrators depend on.

Binomial kernels are monotonic. An equiripple halfband is sharper on its own, but in a cascade its passband ripple compounds stage over stage.

== Element Type

The element type `T` is a template parameter, so the filter works with native integer or floating point samples (for example `uint16_t` or `float`). The `operator()` is `constexpr`.

CAUTION: For integral `T`, the weighted sum reaches `2^(N-1)` times the input magnitude before the divide. A `T` that the usual arithmetic conversions do not promote to something wider (that is, a `T` at least as wide as `int`) needs `N-1` bits of headroom. Narrower integer types promote to `int` and are unaffected.

== Include

```c++
#include <q/fx/fast_downsample.hpp>
```

== Declaration

```c++
template <std::size_t N, typename T>
struct basic_fast_downsample
{
   static constexpr std::size_t order = N-1;

   constexpr T          operator()(T s1, T s2);
};

template <typename T> using fast_downsample_2 = basic_fast_downsample<2, T>;
template <typename T> using fast_downsample_3 = basic_fast_downsample<3, T>;
template <typename T> using fast_downsample_4 = basic_fast_downsample<4, T>;
template <typename T> using fast_downsample_5 = basic_fast_downsample<5, T>;

// Retained for backward compatibility
template <typename T> using fast_downsample = fast_downsample_3<T>;
```

== Expressions

=== Notation

`N`             :: Tap count, `2` or greater.
`T`             :: Element type, e.g. `float` or `uint16_t`.
`D`             :: A `basic_fast_downsample<N, T>` type.
`ds`, `a`, `b`  :: Objects of type `D`.
`s1`, `s2`      :: A consecutive pair of input samples of type `T`.

=== Type Construction

[cols="1,1"]
|===
| Expression                        | Semantics

| `basic_fast_downsample<N, T>`     | Instantiate a `basic_fast_downsample` type
                                      given `N` (tap count) and `T` (element
                                      type).
| `fast_downsample_2<T>`            | Pre declared two-tap type given `T`.
| `fast_downsample_3<T>`            | Pre declared three-tap type given `T`.
| `fast_downsample_4<T>`            | Pre declared four-tap type given `T`.
| `fast_downsample_5<T>`            | Pre declared five-tap type given `T`.
|===

==== Examples:

```c++
using my_downsample_type1 = basic_fast_downsample<5, float>;
using my_downsample_type2 = fast_downsample_3<std::uint16_t>;
```

=== Constructors and Assignment

[cols="1,1"]
|===
| Expression    | Semantics

| `D()`         | Construct a `D` with its filter state at 0.
| `D(ds)`       | Copy construct from `D ds`.
| `a = b`       | Assign `b` to `a`.
|===

NOTE: C++ brace initialization may also be used.

=== Function Call

[cols="1,1,1"]
|===
| Expression     | Semantics                                        | Return Type

| `ds(s1, s2)`   | Filter and decimate the consecutive input pair
                   `s1`, `s2` into one output sample at half the rate. | `T`
|===

NOTE: Each call consumes two input samples and produces one output, so the output stream runs at half the input rate. Feed the input in consecutive pairs.

=== Access

[cols="1,1,1"]
|===
| Expression     | Semantics                                        | Return Type

| `D::order`     | Get the number of rounds of two-sample
                   averaging, `N-1`.                                | `std::size_t`
|===

=== Example

Halve the sample rate of the input samples `in` into the output samples `out`, two input samples at a time:

```c++
namespace q = cycfi::q;

auto ds = q::fast_downsample_3<float>{};              <1>

for (std::size_t i = 0; i + 1 < in.size(); i += 2)
   out[i / 2] = ds(in[i], in[i + 1]);                 <2>
```

<1> Construct a three-tap downsampler for `float` samples.
<2> Filter and decimate a consecutive pair of input samples into one output
    sample.

Decimate 16 consecutive input samples by 16, in four stages:

```c++
#include <q/fx/fast_downsample.hpp>
...
namespace q = cycfi::q;

float s[16];                        // 16 consecutive input samples
...
q::fast_downsample_5<float> ds1, ds2, ds3, ds4;        <1>

float a[8], b[4], c[2], out;
for (int i = 0; i != 8; ++i)
   a[i] = ds1(s[i*2], s[i*2+1]);                      <2>
for (int i = 0; i != 4; ++i)
   b[i] = ds2(a[i*2], a[i*2+1]);
for (int i = 0; i != 2; ++i)
   c[i] = ds3(b[i*2], b[i*2+1]);
out = ds4(c[0], c[1]);                                <3>
```

<1> Construct four five-tap downsamplers, one per stage.
<2> Halve the rate at each stage, from 16 samples to 8, 4, 2, and 1.
<3> Get the one output sample, at 1/16 of the input rate.
