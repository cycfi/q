= Moving Sum

include::../../common.adoc[]

== Overview

The moving sum involves adding a specified number of values in a sequence of data points: the moving sum window. The window moves through the data one point at a time as new samples arrive, and at each step, the sum of the data points within the window is calculated. Instead of calculating the sum of all elements in the window each time, an efficient scheme keeps a continuous total and subtracts the last element that will fall off the window when a new sample arrives.

image::moving-sum.svg[alt="Moving Sum", width=500px, align=center, title="Moving Sum"]

When data is pushed into a moving sum, the element indices are shifted by one position to accommodate the incoming data. This logical shifting ensures that the newest data is stored in the first index (index 0), while the oldest data is pushed out of the buffer. The physical location of data does not actually change, only the indices.

`basic_moving_sum` is a template class representing moving sums with provision for specifying the element type, `T`. Integers are typically faster than floating point and are not prone to round-off errors. It is implemented internally using a ring buffer. Refer to {ring_buffer}.

`basic_moving_sum_ref` computes the same moving sum over a history the caller owns, with no buffer of its own. Any number of them can share one history, each with its own window.

== The Accumulator

The running sum is kept in a second type, `Accumulator`. Its default is `T` promoted one step: `double` for `float`, `long double` for `double`, and the next wider integer for an integer type. With a floating-point `T`, each sample added and removed leaves a little round-off in the sum, and the wider type keeps that from building up over a long run.

On a target without double-precision hardware, such as a Cortex-M4F, every `double` operation runs in software. There, give `float` as the `Accumulator`. A floating-point `Accumulator` no wider than `T` re-sums to bound its drift: a second sum restarts every `size()` samples and replaces the running sum each time it spans a full window. `basic_moving_sum_ref` takes the same `Accumulator`, and re-sums the same way.

```c++
#include <q/fx/moving_sum.hpp>
#include <q/support/literals.hpp>
...
namespace q = cycfi::q;
using namespace q::literals;

float sps;                                 // samples per second
...

// A 20 ms window on a Cortex-M4F, summed in float
q::basic_moving_sum<float, float> sum{20_ms, sps};
```

== Moving Sum

=== Include

```c++
#include <q/fx/moving_sum.hpp>
```

=== Declaration

```c++
template <typename T, typename Accumulator = decltype(promote(T()))>
struct basic_moving_sum
{
   using value_type = T;
   using accumulator_type = Accumulator;

                  basic_moving_sum(std::size_t max_size);
                  basic_moving_sum(duration d, float sps);

   value_type     operator()(value_type s);
   value_type     operator()() const;

   value_type     sum() const;
   std::size_t    size() const;
   void           resize(std::size_t size, bool update = false);
   void           resize(duration d, float sps, bool update = false);
   void           clear();
   void           fill(T val);
};

using moving_sum = basic_moving_sum<float>;
```

[cols="1,1,1"]
|===
| Expression                     | Semantics                                         | Return Type

| `ms.resize(size [, update])`   | Resize the moving sum window to the number

==== Example

Sum the input samples `in` over a 20 ms window, at `sps` samples per second:

```c++
namespace q = cycfi::q;
using namespace q::literals;

auto sum = q::moving_sum{20_ms, sps};                    <1>

for (auto s : in)
{
   auto total = sum(s);                                   <2>
   // Use total, the sum of the last 20 ms of samples
}
```

<1> Construct a moving sum with a 20 ms window.
<2> Add the sample and return the sum over the window.

== Moving Sum Ref

`basic_moving_sum_ref` is `basic_moving_sum` without the storage: it keeps only the window size and the running sum, and reads the departing sample from a history the caller owns. One history serves any number of these, each with its own window.

=== Include

```c++
#include <q/fx/moving_sum.hpp>
```

=== Declaration

```c++
template <typename T, typename Accumulator = decltype(promote(T()))>
struct basic_moving_sum_ref
{
   using value_type = T;
   using accumulator_type = Accumulator;

                  basic_moving_sum_ref(std::size_t size);
                  basic_moving_sum_ref(duration d, float sps);

   value_type     operator()(value_type s, value_type departing);

   template <concepts::IndexableContainer History>
   value_type     operator()(value_type s, History const& hist);

   value_type     operator()() const;

   value_type     sum() const;
   std::size_t    size() const;
   void           resize(std::size_t size);
   void           resize(duration d, float sps);

   template <concepts::IndexableContainer History>
   void           resize(std::size_t size, History const& hist);

   void           clear();
   void           set(accumulator_type sum);
};

using moving_sum_ref = basic_moving_sum_ref<float>;
```

==== Function Call

[cols="1,1,1"]
|===
| Expression      | Semantics                                  | Return Type

| `msr(s, hist)`  | Process the input sample `s`, reading the
                    departing sample from `hist`, and return
                    the current sum.                           | `T`
| `msr(s, x)`     | Process the input sample `s`, given `x`
                    (the departing sample), and return the
                    current sum.                               | `T`
| `msr()`         | Get the current sum.                       | `T`
|===

WARNING: The caller owns the history. It holds at least `msr.size()` samples, `hist[0]` the most recent, so a history shared by several views is sized to the longest window. Every view reads it before the caller pushes the current sample, and the caller pushes exactly once per sample.

`msr(s, x)` takes both ends of the window directly, so the window can hold a function of the history. `msr(s * s, x * x)`, with `x` read from `hist[msr.size() - 1]`, sums the squares of a history of the raw signal; the same history serves a plain sum at once.

==== Accessors

[cols="1,1,1"]
|===
| Expression         | Semantics                            | Return Type

| `msr.sum()`        | Get the current sum.                 | `T`
| `msr.size()`       | Get the window size (in samples).    | `std::size_t`
|===

==== Mutators

[cols="1,1,1"]
|===
| Expression                | Semantics                                   | Return Type

| `msr.resize(size)`        | Set the window to `size` samples, and
                              clear the sum.                              | `void`
| `msr.resize(d, sps)`      | Set the window given `d` (window duration)
                              and `sps` (samples per second), and clear
                              the sum.                                    | `void`
| `msr.resize(size, hist)`  | Set the window to `size` samples, adding
                              or subtracting the samples in `hist` that
                              enter or leave the window.                  | `void`
| `msr.set(sum)`            | Set the current sum.                        | `void`
|===

NOTE: `resize` has no maximum: the history bounds the window, and the caller keeps it at least `size` samples long. A running sum cannot rebuild itself from the history. When the function of the history that the window holds changes, compute the new sum and pass it to `set`.

==== Example

Sum the input samples `in` over windows of 16 and 64 samples, sharing one
history:

```c++
namespace q = cycfi::q;

auto hist = q::ring_buffer<float>{64};                   <1>
hist.clear();

auto fast = q::moving_sum_ref{16};                       <2>
auto slow = q::moving_sum_ref{64};

for (auto s : in)
{
   auto fast_sum = fast(s, hist);                        <3>
   auto slow_sum = slow(s, hist);
   hist.push(s);                                         <4>
   // Use fast_sum and slow_sum
}
```

<1> Construct the history, sized to the longest window, and clear it to zero.
<2> Construct two moving sums over the history, with windows of 16 and 64
    samples.
<3> Add the sample to each sum and return it, reading the departing sample
    from the history.
<4> Push the sample once, after every view has read the history.
