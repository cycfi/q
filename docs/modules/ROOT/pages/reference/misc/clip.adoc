= Clippers

include::../../common.adoc[]

== Overview

Three waveshapers for bounding (and coloring) a signal:

* `hard_clip` hard-limits to `±max`: values inside the range pass through bit-exactly; values outside are clamped. Zero coloration below the ceiling, hard corners at it (strong high harmonics).
* `cubic_clip` bounds to ±1 with a smooth cubic (`1.5s − 0.5s³` after a ±1 clamp), so the transfer curve flattens gradually into the rails instead of cornering. Gentle, tape-like saturation with mild odd-harmonic coloration near the rails. (The cubic is a polynomial fit of a quarter sine -- very close to `sin(½π·s)`, but cheaper and `constexpr`.)
* `tanh_clip` bounds to `±max` (default ±1) with a tanh (the exp-based `fast_tanh`), as `max·tanh(s/max)` -- unit slope at 0, so small signals pass essentially unchanged. tanh saturates over all reals, so there is no input clamp: louder inputs roll off gradually and stay distinguishable instead of pinning flat. It is branchless, approximate, and not `constexpr`; see <<cost>>.

The former names `clip` and `soft_clip` remain as deprecated aliases for `hard_clip` and `cubic_clip`.

== Include

```c++
#include <q/fx/clip.hpp>
```

== Declaration

```c++
struct hard_clip
{
   constexpr      hard_clip(decibel max);
   constexpr      hard_clip(float max = 1.0f);

   constexpr float operator()(float s) const;
};

struct cubic_clip : hard_clip
{
   constexpr float operator()(float s) const;
};

struct tanh_clip
{
   tanh_clip(decibel max);
   tanh_clip(float max = 1.0f);

   float operator()(float s) const;
};

// Deprecated former names:
using clip [[deprecated]] = hard_clip;
using soft_clip [[deprecated]] = cubic_clip;
```

== Expressions

=== Notation

`c`         :: Object of type `hard_clip`, `cubic_clip`, or `tanh_clip`.
`max`       :: The clamp level: a `float`, or a `decibel` level.
`s`         :: Input sample. A `float`.

=== Constructors

[cols="1,1"]
|===
| Expression            | Semantics

| `hard_clip(max)`      | Construct a hard clip at `±max` (`float`, or a
                          `decibel` level converted to linear).
| `hard_clip()`         | Construct a hard clip at ±1.0.
| `cubic_clip()`        | Construct a cubic soft clip; range ±1.0.
| `tanh_clip(max)`      | Construct a tanh soft clip at `±max` (`float`,
                          or a `decibel` level converted to linear); the
                          curve is `max·tanh(s/max)`, unit slope at 0.
| `tanh_clip()`         | Construct a tanh soft clip; range ±1.0.
|===

=== Function Call

[cols="1,1,1"]
|===
| Expression      | Semantics                                   | Return Type

| `c(s)`          | The bounded sample. `hard_clip`: clamp to
                    `±max`. `cubic_clip`: clamp to ±1, then
                    `1.5s − 0.5s³`. `tanh_clip`: `max·tanh(s/max)`. | `float`
|===

NOTE: `cubic_clip` operates on the ±1 domain (its slope reaches zero exactly at ±1, and it maps ±1 to ±1, pinned flat beyond). `tanh_clip` needs no clamp: tanh saturates asymptotically, keeping more headroom for loud inputs.

[#cost]
== Cost

A micro-benchmark, `test/benchmark/soft_clip_bench.cpp`, built with Apple clang 21 at `-O3` and run on an Apple M2; the median of five runs:

[cols="2,1"]
|===
| Operation                         | ns / call

| `fasttanh` (exp, branchless)      | ≈ 0.9
| `fast_rational_tanh` (raw)        | ≈ 0.9
| `hard_clip`                       | ≈ 0.9
| `tanh_clip`                       | ≈ 0.9
| `cubic_clip`                      | ≈ 0.9
| `std::tanh`                       | ≈ 2.2
|===

All but `std::tanh` measure the same, 0.87 to 0.91 ns. That is about three cycles at the M2's 3.5 GHz, the latency of the floating-point add that sums every result in the benchmark's loop. On this machine the benchmark cannot rank them; it shows that each costs no more than that add, and that `std::tanh` costs about 2.5 times as much. All are negligible at one call per sample.

All three compute in `float` throughout, constants included. On a desktop that makes no measurable difference. On a target whose FPU is single precision only, such as a Cortex-M4F, it keeps them out of the software routines that `double` arithmetic runs in there.
