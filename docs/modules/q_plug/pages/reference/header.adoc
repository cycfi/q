= The Header

include::../common.adoc[]

== Overview

The header is the row along the top of a plugin's editor: a main menu at
the left, the preset the plugin is on beside it, and at the right the zoom
buttons and a logo, if there is one. It is the same in every plugin unless
a plugin changes it, so a user who knows where the presets and the zoom are
in one QPlug plugin finds them in the same place in the next.

Every item on it works through the {controller}, with nothing for the
plugin to connect. The {presenter} calls `make_header` from `on_attach` and
puts the result at the top of its content, as the `anna_5` example does:

[source,c++]
----
#include <q_plug/presenter.hpp>
#include <elements.hpp>
...
namespace q_plug = cycfi::q_plug;
namespace elements = cycfi::elements;
using namespace elements;

auto constexpr bkd_color = rgba(35, 35, 37, 255);

class my_presenter : public q_plug::presenter
{
   ...
   void on_attach(elements::view& view_) override
   {
      view_.content(
         fixed_size({920, 568},
            margin({10, 10, 10, 10},
               vtile(
                  hold(make_header())
                  ...
               )
            )
         ),
         box(bkd_color)
      );
   }
};
----

image::q_plug/header-parts.svg[alt="the header and the virtual that builds each part", width=620px, role=center]

`make_header` builds the row by calling `make_main_menu`,
`make_preset_menu`, `header_items`, `make_zoom_buttons` and `logo`, from
left to right. Overriding one of them changes that part of the row only.

NOTE: `make_preset_menu` requires the view, so the header is made from
`on_attach`. The view does not exist yet in the presenter's constructor.

== The Main Menu

The main menu is the icon button at the left. It is built a section at a
time, in the order below, with a spacer after each section that has items,
except the last.

image::q_plug/main-menu-sections.svg[alt="the main menu, and the virtual that fills each section", width=620px, role=center]

Save Preset saves the state under the name shown and clears the edited
mark. It is enabled while the name is not blank, is not a factory preset's,
and the preset is edited, as the `*` beside the name shows.

Save Preset As opens a dialog with the name shown already in the field,
saves the state to the user's preset file under the name entered, and
shows that name in the header. A factory preset's name opens an alert and
saves nothing: a changed factory sound is saved under a name of the
user's own. An empty name does nothing. A file that cannot be written
opens an alert, and the header keeps the name it showed.

Delete Preset is enabled while the name shown is not blank and is not a
factory preset's. It deletes the user preset and clears the name in the
header. A file that cannot be written opens an alert.

Zoom In, Zoom Out and Actual Size carry the presenter's zoom shortcuts: the
action key, Command on macOS and Control elsewhere, with plus, minus and
zero. The {zoom} page covers the stops they walk and where the scale is
kept.

About opens a message box with the plugin's name, its version and its
vendor, as `info()` gives them.

== The Preset Menu

The button beside the main menu shows the preset the plugin is on, with a
leading `*` while it is edited. The name is read from the controller as the
button is drawn, so any refresh shows the current one: a preset loaded,
saved or deleted, or a parameter moved from the panel or from the host. The
button observes every parameter model for that last case, and is redrawn
when one of them moves.

The list is built each time the menu opens, so it includes a preset saved a
moment ago and leaves out one just deleted. Each line carries the name, and
at the right whose preset it is, factory or user. Past twelve presets the
list scrolls, at six tenths of the editor's height.

== The Zoom Buttons and the Logo

Two icon buttons at the right do what Zoom Out and Zoom In do in the main
menu. Expand sits outermost, nearest the edge the window grows towards.

`logo` returns null in the base. A plugin that overrides it gets its
element at the far end of the row, past the zoom buttons.

```c++
#include <q_plug/presenter.hpp>
```

== Declaration

The part of `presenter` that builds the header:

```c++
class presenter
{
public:

   using element_ptr = elements::element_ptr;

protected:

   using row = std::vector<element_ptr>;
   using menu = std::vector<element_ptr>;

   virtual element_ptr     make_header();
   virtual element_ptr     make_main_menu();
   virtual element_ptr     make_preset_menu();
   virtual element_ptr     make_zoom_buttons();
   virtual element_ptr     logo();

   virtual void            header_items(row& items);

   virtual void            preset_menu_items(menu& items);
   virtual void            view_menu_items(menu& items);
   virtual void            plugin_menu_items(menu& items);
   virtual void            about_menu_items(menu& items);
};
```

== Client Interface

The header is built by protected virtual members of the {presenter}, a base
class meant to be derived from and not instantiated directly. The client's
presenter calls `make_header` from `on_attach`, and overrides the function
for the part of the header it changes. To add to a part, the override calls
the base first and pushes onto the items the base added; to replace a part,
it does not call the base.

`element_ptr make_header() override;` ::
    Build the header row, calling the functions below from left to right.
    Call it from `on_attach`, and put the result at the top of the content.
`element_ptr make_main_menu() override;` ::
    Build the menu button at the left and its menu, calling the four
    `_menu_items` functions in order.
`element_ptr make_preset_menu() override;` ::
    Build the button that shows the preset, and the list it drops.
`void header_items(row& items) override;` ::
    Add elements to the row, between the preset menu and the zoom buttons.
    Empty in the base.
`element_ptr make_zoom_buttons() override;` ::
    Build the two zoom buttons at the right.
`element_ptr logo() override;` ::
    Return an element for the far right of the row. Returns null in the
    base.
`void preset_menu_items(menu& items) override;` ::
    Add Save Preset, Save Preset As and Delete Preset to the main menu.
`void view_menu_items(menu& items) override;` ::
    Add Zoom In, Zoom Out and Actual Size to the main menu.
`void plugin_menu_items(menu& items) override;` ::
    Add the plugin's own items to the main menu. Empty in the base.
`void about_menu_items(menu& items) override;` ::
    Add About, with the plugin's name, to the main menu.

The items are pushed in the order they are to appear, and the spaces
between them are elements of their own.

== Example

Put power and bypass toggles on the row, and add Revert and Configuration
to the main menu:

```c++
#include <q_plug/presenter.hpp>
#include <elements.hpp>
...
namespace q_plug = cycfi::q_plug;
namespace elements = cycfi::elements;
using namespace cycfi::elements;

class my_controller : public q_plug::controller
{
public:

   enum { power_id, bypass_id };
   ...
};
...

class my_presenter : public q_plug::presenter
{
public:
                        my_presenter(my_controller& ctl);

protected:

   void                 on_attach(elements::view& view_) override;
   void                 header_items(row& items) override;              <1>
   void                 plugin_menu_items(menu& items) override;        <2>
};

void my_presenter::header_items(row& items)
{
   auto const& params = ctrl().parameters();

   auto power = share(toggle_icon_button(icons::power, 1.2f));
   auto bypass = share(toggle_icon_button(icons::block, 1.2f));
   bind(my_controller::power_id, power, params[my_controller::power_id]);
   bind(my_controller::bypass_id, bypass, params[my_controller::bypass_id]);

   items.push_back(share(hspace(12)));                                  <3>
   items.push_back(share(align_middle(hold(power))));
   items.push_back(share(hspace(4)));
   items.push_back(share(align_middle(hold(bypass))));
}

void my_presenter::plugin_menu_items(menu& items)
{
   auto revert = menu_item("Revert");
   auto config = menu_item("Configuration...");

   revert.is_enabled =                                                  <4>
      [this]()
      {
         return !ctrl().preset_name().empty() && ctrl().preset_edited();
      };
   revert.on_click =                                                    <5>
      [this]()
      {
         ctrl().load_preset(ctrl().preset_name());
         if (auto v = view())
            v->refresh();
      };

   config.on_click = [this]() { /* open a dialog of the plugin's own */ };

   items.push_back(share(std::move(revert)));
   items.push_back(share(std::move(config)));
}
```

<1> Override `header_items`, which is empty in the base, so the override
    does not call it.
<2> Override `plugin_menu_items`, also empty in the base.
<3> Push each element in the order it appears, with the spaces between them
    as elements of their own. A toggle binds like any other control, and a
    click is one edit.
<4> Enable Revert only while a preset is named and edited.
<5> Load the preset shown again, which restores its values, passes them on
    to the host and clears the edited mark, then refresh the view to redraw
    the header.

See <<_client_interface>> for more info.
