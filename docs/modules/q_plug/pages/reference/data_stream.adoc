= Data Streams

include::../common.adoc[]

== Overview

A plugin's state crosses to the host as bytes. The host saves them with the
session and hands them back when the session is opened again. `byte_ostream`
and `byte_istream` are QPlug's two byte streams for that crossing: the
{controller} writes its state to a `byte_ostream` and reads it back from a
`byte_istream`.

Both are interfaces of one function each. The host adapter implements them
over the host's own streams, so the controller never deals with a plugin
format. A plugin rarely implements them itself; it does so to save or load
a state outside a host, in a test or a tool.

What goes through them is the controller's state, the JSON object
`ctl.state()` returns, as text. Its layout, and what a plugin adds to it,
is in {controller}.

== Use Case

A test that saves a plugin's state and loads it into another controller,
with no host, implements the two streams over a string:

[source,c++]
----
struct string_ostream : q_plug::byte_ostream
{
   std::int64_t write(void const* data, std::int64_t size) override
   {
      text.append(static_cast<char const*>(data), std::size_t(size));
      return size;
   }

   std::string text;
};

struct string_istream : q_plug::byte_istream
{
   std::int64_t read(void* data, std::int64_t size) override
   {
      auto n = std::min<std::int64_t>(size, text.size() - pos);
      std::memcpy(data, text.data() + pos, std::size_t(n));
      pos += std::size_t(n);
      return n;
   }

   std::string text;
   std::size_t pos = 0;
};

string_ostream out;
REQUIRE(a.save_state(out));

string_istream in;
in.text = out.text;
REQUIRE(b.load_state(in));
----

== Declaration

```c++
namespace cycfi::q_plug
{
   struct byte_ostream
   {
      virtual                 ~byte_ostream() = default;
      virtual std::int64_t    write(void const* data, std::int64_t size) = 0;
   };

   struct byte_istream
   {
      virtual                 ~byte_istream() = default;
      virtual std::int64_t    read(void* data, std::int64_t size) = 0;
   };
}
```

== Expressions

=== Notation

`out`                :: Object of a type derived from `byte_ostream`.
`in`                 :: Object of a type derived from `byte_istream`.
`data`               :: A pointer to `size` bytes.
`size`               :: A `std::int64_t`, a number of bytes.
`ctl`                :: Object of a type derived from `controller`.

=== The Streams

[cols="1,1,1"]
|===
| Expression               | Semantics                          | Return Type

| `out.write(data, size)`  | Write up to `size` bytes. Returns
                             how many were written, or 0 or less
                             on failure.                        | `std::int64_t`
| `in.read(data, size)`    | Read up to `size` bytes. Returns
                             how many were read, 0 at the end,
                             or less than 0 on failure.         | `std::int64_t`
|===

A stream may move fewer bytes than asked, as the host's streams do. The
controller's side allows for that: it writes in a loop until every byte
has gone, and reads in pieces of 4096 bytes until `read` returns 0.

=== Saving and Loading

[cols="1,1,1"]
|===
| Expression               | Semantics                          | Return Type

| `ctl.save_state(out)`    | Write the state, as JSON text.
                             False if a write failed.           | `bool`
| `ctl.load_state(in)`     | Read a state and take it. False
                             if a read failed, the text is not
                             JSON, or the state is refused.     | `bool`
|===

A state is refused when it was written by another plugin or by a later
version of this one (see {controller}). A refused or unreadable state
leaves the parameters as they were.
