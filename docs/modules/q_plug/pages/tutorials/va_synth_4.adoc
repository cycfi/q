= VA Synth 4: Drawn Envelopes

include::../common.adoc[]

== Overview

Stage 4 changes no sound. It replaces the eight envelope sliders with two
envelopes drawn as their own shapes, one for the VCA and one for the VCF,
each set by dragging its corners. The drawn envelope is a custom Elements
control, `adsr_control`, and it carries four values at once, where a
slider carries one. How a control with several values is bound to four
parameters is the subject of this page.

[IMPORTANT]
====
Read {tutorial-va-synth-3} first, and the tutorials before it. This page
covers only what stage 4 adds; the listings are the parts of stage 4's
files that are new or changed, and the rest is stage 3's. Each
listing's title links to its whole file, and all of stage 4 is in
link:{q-tree}/example/q_plug/va_synth_4[`example/q_plug/va_synth_4`].
====

== Quick Start

As in {tutorial-va-synth-1}, with `va_synth_4` in place of `va_synth_1`.
On macOS and Linux:

[,sh]
----
Q=/path/to/q
cp -R "$Q/example/q_plug/va_synth_4" /tmp/va_synth_4
cd /tmp/va_synth_4
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug -DQ_ROOT="$Q"
cmake --build build
----

On Windows, in a command prompt with the MSVC environment loaded:

[,bat]
----
set Q=C:\path\to\q
xcopy /E /I "%Q%\example\q_plug\va_synth_4" "%TEMP%\va_synth_4"
cd /d "%TEMP%\va_synth_4"
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug -DQ_ROOT="%Q%"
cmake --build build
----

Then start the standalone app:

* macOS: `open "build/products/QPlug VA Synth 4.app"`
* Linux: `"build/products/QPlug VA Synth 4"`
* Windows: `"build\products\Standalone-q_plug-va-synth-4_standalone\QPlug VA Synth 4.exe"`

== The Control

.link:{q-src}/example/q_plug/va_synth_4/adsr_control.hpp[adsr_control.hpp]
[source,c++]
----
#include <elements.hpp>
...
class adsr_control : public elements::tracker<> // <1>
{
public:
   ...
   void              attack_value(float v)   { _attack = v; } // <2>
   void              decay_value(float v)    { _decay = v; }
   ...
   float             attack_value() const    { return _attack; }
   ...
   change_function   on_attack_change; // <3>
   ...
   gesture_function  on_attack_gesture; // <4>
   ...
   void              draw(elements::context const& ctx) override; // <5>
   bool              click( // <6>
   ...
   void              keep_tracking( // <7>
   ...
   bool              cursor( // <8>
   ...
   bool              wants_control() const override { return true; } // <9>

private:
   ...
   struct unit_point // <10>
   {
...
inline auto attack_of(std::shared_ptr<adsr_control> c) // <11>
{
   return elements::make_bindable_proxy(c, &adsr_control::attack_value // <12>
    , c->on_attack_change, &c->on_attack_gesture);
...
inline auto release_of(std::shared_ptr<adsr_control> c)
{
...
}
----
<1> A custom Elements control derives from `tracker`, which follows the
mouse from a press to its release, and overrides four members: `draw`,
`click`, `keep_tracking` and `cursor`.
<2> A setter and a getter per value, where a slider has one of each. The
values are the control's travel, 0 to 1; each parameter's own taper turns
its value into seconds or a level, as a slider's does.
<3> A change callback per value, called when a drag moves that value.
<4> A gesture callback per value, which brackets a drag, so the host
records one movement rather than a hundred.
<5> Draws the shape.
<6> A press takes hold of the corner under the cursor, and the release
lets it go.
<7> Moves the corner being held.
<8> Lights up the corner the mouse is over.
<9> Says the control takes the mouse, as `tracker` already does.
<10> The shape lives in a unit square, and the diagram above it shows its
corners. Attack, decay and release each own a share of the width; the
sustain is a level, drawn as a plateau of fixed width.
<11> Each value handed out as a control of its own, for the binder.
<12> Elements' `make_bindable_proxy` pairs the value's setter with its
change and gesture callbacks. The result binds as a slider does.

----
<1> Each corner of the shape is worked out from the four values, so the
shape always matches them.
<2> The reverse: a corner dragged to a point sets the values it is made
of. The corner of the fall carries two, the decay and the sustain.
<3> The size the control asks for: at least 180 by 90, and free to grow.
<4> Nothing is drawn outside the control's bounds, or a corner near the
edge would leave a mark on the panel that nothing erases.
<5> The envelope, filled under and drawn over; then the three corners,
the live one larger.
<6> A press takes hold of the corner under it, if one is within reach.
<7> The drag begins a gesture on each value the corner carries.
<8> The base follows the mouse from here to the release.
<9> The corner of the fall brackets both of its values.
<10> A drag reports only the values it changed, each through its own
callback.
<11> While the mouse is held, the corner follows it.
<12> The corner under the mouse is drawn larger, so the user sees what a
press would take hold of.

== The Presenter

.link:{q-src}/example/q_plug/va_synth_4/va_synth_presenter.cpp[va_synth_presenter.cpp], the envelopes
[source,c++]
----
   auto vca_env = share(adsr_control{}); // <1>
   auto vcf_env = share(adsr_control{});
   ...
   auto link_envelope = // <2>
      [&](auto env, int attack, int decay, int sustain, int release)
      {
         link(attack, attack_of(env)); // <3>
         ...
         link(release, release_of(env));
   ...
   link_envelope(vca_env, ctl::attack_id, ctl::decay_id // <4>
      , ctl::sustain_level_id, ctl::release_id);
   link_envelope(vcf_env, ctl::filter_attack_id, ctl::filter_decay_id
      , ctl::filter_sustain_level_id, ctl::filter_release_id);
----
<1> One control per envelope, from the example's own `adsr_control.hpp`,
shared, as `bind` takes it (see {tutorial-gain}).
<2> An envelope is bound four times, once per value.
<3> `attack_of(env)` is a control of its own to the binder, so `link`
binds it exactly as it binds a slider, through the parameter's own taper.
<4> The VCA's envelope to stage 1's four parameters, and the VCF's to
stage 2's. The ids are unchanged, so a stage 3 preset reads here.

.link:{q-src}/example/q_plug/va_synth_4/va_synth_presenter.cpp[va_synth_presenter.cpp], the VCA panel
[source,c++]
----
                  panel("VCA",
                        ...
                        hsize(env_width, margin({8, 8, 8, 8}, hold(vca_env))), // <1>
                        ...
                        captioned(hold(volume), "Volume")
----
<1> The envelope takes the place of four sliders, at a fixed width, so the
VCA's and the VCF's line up down the window. The VCF's panel does the
same.

The panel grows to 848 by 524, and `plugin_info` gives the same size.

== The Build

The control has a source file of its own, so the implementation library
lists it:

.link:{q-src}/example/q_plug/va_synth_4/CMakeLists.txt[CMakeLists.txt], the implementation library
[source,cmake]
----
add_library(q_plug_va_synth_4_impl STATIC
   ...
   adsr_control.cpp # <1>
)
----
<1> The drawn envelope. `va_synth.cpp` changes the id, the name, the
description and the view size, and the AudioUnit subtype is `QVs4`.
