= VA Synth 1: The Voice

include::../common.adoc[]

== Overview

`example/q_plug/va_synth_1` is the first of five stages of one polyphonic
synthesizer, each a complete plugin. Stage 1 is the voice: a bandwidth
limited sawtooth through an envelope, sixteen of them, played from a
keyboard, with pitch bend, vibrato from the modulation wheel and the
sustain pedal. Six sliders set the envelope, the velocity sensitivity and
the volume.

image::qplug/va-synth-1-standalone.png[alt="QPlug VA Synth 1 running as a standalone app", title="QPlug VA Synth 1, running as a standalone app on macOS", width=700px, align=center]

[IMPORTANT]
====
Read {tutorial-gain} first. The VA Synth tutorials build on it, and each
builds on the one before, so read them in order. What an earlier page has
explained is not explained again here; a callout points back to it
instead.
====

The synth is Q's own polyphonic synth with a plugin around it. The pool
of voices and how a note takes a voice are the same code, and so is the
voice, less the filter it has in Q, which comes back in stage 2.
{q-tutorial-poly_synth} explains them. What this page covers is what the
plugin adds: parameters that move while notes sound, notes that arrive
from a host, and a panel. The files have the shape Gain's have, with
`va_synth` in place of `gain`, and no `resources/`: the panel draws
everything it shows.

The listings below are the parts of each file that matter. Each title
links to the whole file, and all of stage 1 is in
link:{q-tree}/example/q_plug/va_synth_1[`example/q_plug/va_synth_1`].

== Quick Start

As in {tutorial-gain}, with `va_synth_1` in place of `gain`. On macOS and
Linux:

[,sh]
----
Q=/path/to/q
cp -R "$Q/example/q_plug/va_synth_1" /tmp/va_synth_1
cd /tmp/va_synth_1
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug -DQ_ROOT="$Q"
cmake --build build
----

On Windows, in a command prompt with the MSVC environment loaded:

[,bat]
----
set Q=C:\path\to\q
xcopy /E /I "%Q%\example\q_plug\va_synth_1" "%TEMP%\va_synth_1"
cd /d "%TEMP%\va_synth_1"
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug -DQ_ROOT="%Q%"
cmake --build build
----

Then start the standalone app:

* macOS: `open "build/products/QPlug VA Synth 1.app"`
* Linux: `"build/products/QPlug VA Synth 1"`
* Windows: `"build\products\Standalone-q_plug-va-synth-1_standalone\QPlug VA Synth 1.exe"`

The app listens to every MIDI input connected, so play it from a keyboard.

== The Controller

.link:{q-src}/example/q_plug/va_synth_1/va_synth_controller.hpp[va_synth_controller.hpp], the class
[source,c++]
----
class va_synth_controller : public q_plug::controller
{
public:

   using duration = q::duration; // <1>
   ...
   enum
   {
      attack_id, decay_id, sustain_level_id, release_id, velocity_id // <2>
   ...
   };
   ...
   double               sustain_level() const;   // 0 to 1 // <3>
   ...
   double               velocity() const;         // 0 to 1 // <4>
...
};
----
<1> A time is a {duration}, Q's unit for time, as Gain's volume is a
`q::decibel`.
<2> The indices, one per parameter, in the order `parameters()` lists
them. As in Gain, the plugin addresses a parameter by its index.
<3> The sustain level, as a fraction from 0 to 1, as a Minimoog's sustain
is. In decibels, most of the travel would sit where a held note is all
but gone.
<4> How much of the key's velocity reaches the loudness, also 0 to 1.

.link:{q-src}/example/q_plug/va_synth_1/va_synth_controller.hpp[va_synth_controller.hpp], two of the accessors
[source,c++]
----
inline q::duration va_synth_controller::attack() const
{
   return get_parameter<duration>(attack_id); // <1>
   ...
   return get_parameter<double>(sustain_level_id) / 100.0; // <2>
}
----
<1> A time parameter reads back as a `q::duration`, the way Gain's volume
reads back as a `q::decibel`.
<2> A plain number reads back as a `double`. The panel shows the sustain
in percent, so the accessor divides.

.link:{q-src}/example/q_plug/va_synth_1/va_synth_controller.cpp[va_synth_controller.cpp], the parameters
[source,c++]
----
parameter_list va_synth_controller::parameters() const
{
   ...
   static parameter params[] =
   {
      parameter{1, "Attack", 20_ms} // <1>
         .range((1_ms).rep, (10_s).rep).log().unit("s") // <2>
    ...
    , parameter{3, "Sustain", 50.0}.range(0.0, 100.0).unit("%") // <3>
    , parameter{5, "Release", 500_ms} // <4>
    ...
    , parameter{13, "Velocity", 100.0}.range(0.0, 100.0).unit("%") // <5>
    , parameter{18, "Volume", 0_dB}.range(-60.0, 0.0) // <6>
   };

   return { params };
}
----
<1> An initial value of `20_ms` makes a time parameter, the way `0_dB`
made Gain's volume a decibel parameter.
<2> A range from 1 ms to 10 s, on a logarithmic taper, shown in seconds.
The ear hears time in ratios, hence the log taper, and a range of four
decades puts a label at each decade.
<3> A plain number, with a range and a unit, here a percentage.
<4> The ids skip 4. It belonged to a parameter this stage once had, and an
id is never reused (see {tutorial-gain}).
<5> Ids 6 to 12 are kept for the filter, which arrives in stage 2, so a
preset saved here still reads there.
<6> A decibel parameter, as in Gain, with its own range, -60 to 0 dB.

====

ranges, tapers and units.

== The Processor

.link:{q-src}/example/q_plug/va_synth_1/va_synth_processor.hpp[va_synth_processor.hpp], the envelope config
[source,c++]
----
struct va_synth_envelope_config // <1>
{
   q::duration    attack_rate;
   q::duration    decay_rate;
   q::decibel     sustain_level;
   q::duration    release_rate;
};
----
<1> The settings of each voice's envelope. With no sustain rate in them,
Q's envelope holds its sustain level until the key comes up.

.link:{q-src}/example/q_plug/va_synth_1/va_synth_processor.hpp[va_synth_processor.hpp], the voice
[source,c++]
----
class va_synth_processor
 : public q_plug::midi_processor<va_synth_processor> // <1>
{
public:

   using midi_processor::operator(); // <2>
   ...
   struct voice // <3>
   {
      ...
      float             operator()(float pitch_factor); // <4>
   ...
   };
----
<1> A synth derives from `q_plug::midi_processor`, from
`<q_plug/midi_processor.hpp>`, which is a {processor}
like Gain's, with the same `channels`, `activate`, `reset` and `process`,
and adds MIDI: the host's notes reach this class as Q MIDI 2.0 messages,
whichever dialect the host sent. The class names itself as the template
argument, which is how the base finds its handlers.
<2> Brings the base's handlers into scope beside this class's own. A
message with no handler of its own here reaches the base's default, which
does nothing.
<3> The voice of {q-tutorial-poly_synth}, less its filter. That
tutorial explains the voice, the pool and how a note takes a voice.
<4> What the plugin adds to the voice: it plays at a factor of the pitch
it was struck at, so bend and vibrato move every sounding note together.

.link:{q-src}/example/q_plug/va_synth_1/va_synth_processor.hpp[va_synth_processor.hpp], the synth
[source,c++]
----
   channel_config       channels() const override { return {0, 2}; } // <1>
   ...
   void                 operator()(midi::note_on msg, std::size_t time); // <2>
   ...
   void                 operator()(midi::pitch_bend msg, std::size_t time);
----
<1> An instrument: no audio in, stereo out.
<2> The four messages the synth handles: note-on, note-off, control
change and pitch bend, in MIDI 2.0: `midi` is the header's alias for
`q::midi_2_0`. `time` is the message's frame in the host's block.

.link:{q-src}/example/q_plug/va_synth_1/va_synth_processor.hpp[va_synth_processor.hpp], the bend and the envelope settings
[source,c++]
----
   static constexpr float  bend_range = 2.0f;          // semitones // <1>
   static constexpr float  vibrato_depth = 0.5f;       // semitones
   ...
   struct settings // <2>
   {
   ...
   };
----
<1> Pitch bend reaches two semitones each way, and the wheel's vibrato,
from the sine generator `_lfo`, half a semitone.
<2> The envelope settings last pushed into the voices, so that only a
setting that moved is pushed again.

.link:{q-src}/example/q_plug/va_synth_1/va_synth_processor.cpp[va_synth_processor.cpp], the voice
[source,c++]
----
void voice::on(q::frequency freq, float velocity)
{
   ...
   _env.attack(); // <1>
   ...
   _phase.set(q::frequency{as_float(_freq) * pitch_factor}, _sps); // <2>
   return q::saw(_phase++) * env; // <3>
}
----
<1> Retriggers a voice, a stolen one included, without a click.
<2> The pitch the note was struck at, times the factor bend and vibrato
make.
<3> Q's bandwidth limited sawtooth, {saw_osc}, through the envelope, an
{envelope_gen}. The header includes both, and the {sin_cos_gen} the
vibrato uses.

.link:{q-src}/example/q_plug/va_synth_1/va_synth_processor.cpp[va_synth_processor.cpp], the envelope config

.link:{q-src}/example/q_plug/va_synth_1/va_synth_processor.cpp[va_synth_processor.cpp], activate
[source,c++]
----
void va_synth_processor::activate()
{
   auto const cfg = envelope_config();
   _voices.clear();
   _voices.reserve(num_voices);
   for (std::size_t i = 0; i != num_voices; ++i)
      _voices.emplace_back(cfg, float(sps())); // <1>
----
<1> The pool is built in `activate`, where the sample rate is known. Q's
example builds it when the synth is made.

.link:{q-src}/example/q_plug/va_synth_1/va_synth_processor.cpp[va_synth_processor.cpp], reset
[source,c++]
----
void va_synth_processor::reset()
{
   ...
   for (auto& v : _voices)
   {
      v._env = q::adsr_envelope_gen{cfg, float(sps())}; // <1>
   ...
   }

<1> `reset` silences every voice by rebuilding its envelope, so no note

.link:{q-src}/example/q_plug/va_synth_1/va_synth_processor.cpp[va_synth_processor.cpp], update_envelopes
[source,c++]
----
void va_synth_processor::update_envelopes()
{
   ...
   for (auto& v : _voices)
   {
         ...
         v._env.attack_rate(q::duration{now.attack}, rate); // <1>
   ...
   _pushed = now;
}
----
<1> Q's example sets its envelopes once. A plugin's settings move while
notes sound, so one setter per segment is called, and only for a setting
that moved. A rate changed while its segment runs carries on from where
it is.

.link:{q-src}/example/q_plug/va_synth_1/va_synth_processor.cpp[va_synth_processor.cpp], process
[source,c++]
----
void va_synth_processor::process(in_channels const& /*in*/
 , out_channels const& out)
{
   update_envelopes(); // <1>
   ...
   for (auto frame : out.frames)
   {
      ...
      auto const pitch_factor = std::exp2((_bend + vibrato) / 12.0f); // <2>
      ...
      left[frame] = right[frame] = mix * headroom * _volume(volume); // <3>
...
}
----
<1> The envelopes are brought up to date once per call, which is enough
for the reason Gain reads its target once per call.
<2> Twelve semitones is a doubling, so bend and vibrato, in semitones,
become one ratio.
<3> The mix, scaled by the smoothed volume and by `headroom`, 0.3, the
room left for sixteen voices at once, to both channels. Q's example
soft-clips after this, since it plays straight to an audio device. A
plugin has its volume control and the host's meter instead, so nothing
shapes the sound on the way out.

.link:{q-src}/example/q_plug/va_synth_1/va_synth_processor.cpp[va_synth_processor.cpp], the notes
[source,c++]
----
void va_synth_processor::operator()(midi::note_on msg, std::size_t)
{
   ...
   note_on(msg.key(), float(msg.velocity()) / 65535); // <1>

{

      sustain(msg.value() >= 0x80000000u); // <2>

      _wheel = float(msg.value()) / 4294967295.0f; // <3>

   ...

void va_synth_processor::note_on(std::uint8_t key, float velocity)
{
   allocate(key).on(midi::note_frequency(key), sensed(velocity)); // <5>
...

{
   ...
   return (1.0f - s) + s * velocity; // <6>

----
<1> A MIDI 2.0 velocity is 16 bits. A MIDI 1.0 note-on at velocity 0
never reaches this handler: it arrives as the note-off it means.
<2> A MIDI 2.0 controller value is 32 bits. The sustain pedal is down from
the centre up.
<3> The modulation wheel, 0 to 1, sets the vibrato's depth.
<4> Pitch bend, 32 bits centred on `midi::pitch_bend::center`, scaled to
the bend range.
<5> `midi::note_frequency` is the key's pitch.
<6> Velocity sensitivity mixes the key's velocity with full: at 0 every
note is the same.

.link:{q-src}/example/q_plug/va_synth_1/va_synth_processor.cpp[va_synth_processor.cpp], the sustain pedal

{
         ...

            v._held = true; // <1>

<1> With the pedal down, a key coming up marks its voice held rather

.link:{q-src}/example/q_plug/va_synth_1/va_synth_processor.cpp[va_synth_processor.cpp], the pool
[source,c++]
----
voice& va_synth_processor::allocate(std::uint8_t key) // <1>
{
   auto free = std::ranges::find_if(
      _voices, [](voice const& v) { return !v.active(); });

   voice& v = (free != _voices.end())?
      *free
    : *std::ranges::min_element(_voices, {}, &voice::_order);

   v._key = key;
   v._order = ++_order;
   v._held = false;      // struck again: the pedal is no longer holding it
   return v;
}
----
<1> A free voice, or the oldest sounding one, as in
{q-tutorial-poly_synth}.

== The Plugin

`va_synth.cpp` is Gain's `gain.cpp` with the names changed, and a
different identity:

.link:{q-src}/example/q_plug/va_synth_1/va_synth.cpp[va_synth.cpp], the identity
[source,c++]
----
   plugin_info const& info()
   {
         ...
         "instrument", // <1>
      ...
      static plugin_info const i = // <2>
      {
      ...
      return i;
----
<1> `instrument` puts the plugin in a host's instrument menu, and a host
that reads the features does not offer it as an insert. `synthesizer` and
`stereo` describe it further.
<2> The view size is the panel's `fixed_size`. The state version is 2,
since stage 1 once kept its sustain in decibels and now keeps it in
percent, which changed what a saved value means.

== The Build

`CMakeLists.txt` is Gain's with the names changed, and two differences in
kind. `AUV2_INSTRUMENT_TYPE` is `aumu`, a music device, where Gain's was
`aufx`, an effect. `q_plug_add_resources` names no files, since the panel
draws everything it shows; the fonts go in all the same.

== Running

Inside Q's build, as {setup} describes, the synth is built with
everything else. The validation tests of all five stages run with:

[,sh]
----
ctest --test-dir cmake-build-debug -R va_synth
----

The products are named `QPlug VA Synth 1`, laid out as Gain's are, and
install the same way. Insert the synth on an instrument track, open its
editor, and play: the bend and modulation wheels and the sustain pedal
work from the first note.
