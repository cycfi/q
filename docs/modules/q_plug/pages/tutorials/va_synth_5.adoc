= VA Synth 5: Presets

include::../common.adoc[]

== Overview

Stage 5 is the finished instrument. It adds the standard {header} along
the top of the editor, with the preset menu and the zoom buttons, and
eleven factory presets that ship with the plugin: Classic Poly, Brass,
Soft Pad, Pluck, Fat Bass, Acid, Strings, Organ, Lead, Clav and Sweep.
The sound and the controls are stage 4's.

[IMPORTANT]
====
Read {tutorial-va-synth-4} first, and the tutorials before it. This page
covers only what stage 5 adds; the listings are the parts of stage 5's
files that are new or changed, and the rest is stage 4's. Each
listing's title links to its whole file, and all of stage 5 is in
link:{q-tree}/example/q_plug/va_synth_5[`example/q_plug/va_synth_5`].
====

Presets need no code of the plugin's own. The {controller} base loads,
saves and deletes them, and the header offers them to the user. What the
plugin supplies is a file of factory presets, and one call that puts the
header on the panel.

== Quick Start

As in {tutorial-va-synth-1}, with `va_synth_5` in place of `va_synth_1`.
On macOS and Linux:

[,sh]
----
Q=/path/to/q
cp -R "$Q/example/q_plug/va_synth_5" /tmp/va_synth_5
cd /tmp/va_synth_5
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug -DQ_ROOT="$Q"
cmake --build build
----

On Windows, in a command prompt with the MSVC environment loaded:

[,bat]
----
set Q=C:\path\to\q
xcopy /E /I "%Q%\example\q_plug\va_synth_5" "%TEMP%\va_synth_5"
cd /d "%TEMP%\va_synth_5"
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug -DQ_ROOT="%Q%"
cmake --build build
----

Then start the standalone app:

* macOS: `open "build/products/QPlug VA Synth 5.app"`
* Linux: `"build/products/QPlug VA Synth 5"`
* Windows: `"build\products\Standalone-q_plug-va-synth-5_standalone\QPlug VA Synth 5.exe"`

Pick a preset from the header's preset menu and play.

== The Factory Presets

`factory_presets.json` is one JSON object, preset name to state, in the
form the controller saves a state in:

.link:{q-src}/example/q_plug/va_synth_5/factory_presets.json[factory_presets.json], the first of its eleven presets
[source,json]
----
{
   "Classic Poly": { // <1>
      "plugin": "com.qplug.va_synth_5", // <2>
      "version": 2, // <3>
      "params": [
         {
            "id": 1, // <4>
            "name": "Attack",
            "value": 0.01 // <5>
         },
         ...
         {
            "id": 6, // <6>
            "name": "Cutoff",
            "value": 500.0
         },
         ...
      ]
   },
   ...
}
----
<1> The preset's name, as the menu lists it.
<2> The plugin the state belongs to, its `plugin_info` id.
<3> The state version, `plugin_info`'s, which is 2 since stage 1 (see
{tutorial-va-synth-1}).
<4> Each parameter by its id, the identity a preset holds it by. The name
is there for the reader.
<5> Values are in the parameter's own units: seconds for a time, hertz
for the cutoff, percent for a sustain level, decibels for the volume. The
attack here is 10 ms.
<6> Stage 2's filter, at ids 6 to 12, and after it the velocities, the
chorus and the volume, seventeen parameters in all.

A factory preset cannot be overwritten or deleted. The user's own presets
go in a `presets.json` of their own.

====
*In depth:* xref:reference/controller.adoc#_presets[Presets], in
{controller}, for where each file lives and how a name shown as edited
is tracked.
====

== The Presenter

.link:{q-src}/example/q_plug/va_synth_5/va_synth_presenter.cpp[va_synth_presenter.cpp], the header
[source,c++]
----
      fixed_size({920, 568}, // <1>
               ...
               hold(make_header()), // <2>
----
<1> The panel grows to 920 by 568, and `plugin_info` gives the same size.
<2> `make_header` builds the standard header, which the {presenter} base
provides: the main menu, the preset menu with the current preset's name,
and the zoom buttons. Put at the top of the content, it needs no other
wiring.

[TIP]
====
*In depth:* {header}, for what the header holds and how a plugin
customizes it, and {zoom}, for the zoom it offers.
====

== The Build

The factory presets are a resource, copied beside the plugin with the
fonts:

.link:{q-src}/example/q_plug/va_synth_5/CMakeLists.txt[CMakeLists.txt], the resources
[source,cmake]
----
q_plug_add_resources(q_plug-va-synth-5
   "${CMAKE_CURRENT_SOURCE_DIR}/factory_presets.json") # <1>
----
<1> The controller finds `factory_presets.json` among the plugin's
resources, where this call puts it. `q_plug_add_resources` also makes a
changed preset file relink the plugin, so an edit to it reaches the next
build.

`va_synth.cpp` changes the id, the name, the description and the view
size, and the AudioUnit subtype is `QVs5`.
