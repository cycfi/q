= Anna III: The Chorus
:page-aliases: tutorials/va_synth_3.adoc

include::../common.adoc[]

== Overview

Stage 3 adds a chorus after the voices: the first effect, and the first
part of the panel that is not a voice control. A chorus is a short delay
whose length a slow sine sweeps, mixed with the dry signal. The copy
drifts a little sharp and flat against the original, which is what
thickens it. Three sliders set how fast it sweeps, how far, and how much
of it is heard.

image::qplug/anna-3-standalone.png[alt="Anna III running as a standalone app", title="Anna III, running as a standalone app on macOS", width=700px, align=center]

[IMPORTANT]
====
Read {tutorial-anna-2} first, and the tutorials before it. This page
covers only what stage 3 adds; the listings are the parts of stage 3's
files that are new or changed, and the rest is stage 2's. Each
listing's title links to its whole file, and all of stage 3 is in
link:{q-tree}/example/q_plug/anna_3[`example/q_plug/anna_3`].
====

The chorus is the example's own, in a new file, `chorus.hpp`. It is built
from two Q parts, a fractional {q-delay} and a {sin_cos_gen}.

== Quick Start

As in {tutorial-anna-1}, with `anna_3` in place of `anna_1`.
On macOS and Linux:

[,sh]
----
Q=/path/to/q
cp -R "$Q/example/q_plug/anna_3" /tmp/anna_3
cd /tmp/anna_3
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug -DQ_ROOT="$Q"
cmake --build build
----

On Windows, in a command prompt with the MSVC environment loaded:

[,bat]
----
set Q=C:\path\to\q
xcopy /E /I "%Q%\example\q_plug\anna_3" "%TEMP%\anna_3"
cd /d "%TEMP%\anna_3"
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug -DQ_ROOT="%Q%"
cmake --build build
----

Then start the standalone app:

* macOS: `open "build/products/Anna III.app"`
* Linux: `"build/products/Anna III"`
* Windows: `"build\products\Standalone-q_plug-anna-3_standalone\Anna III.exe"`

== The Chorus

.link:{q-src}/example/q_plug/anna_3/chorus.hpp[chorus.hpp]
[source,c++]
----
#include <q/fx/delay.hpp> // <1>
...
#include <q/synth/gen/sin_cos_gen.hpp>
...
class chorus
{
public:

                     chorus( // <2>
                        q::duration base, q::duration depth
                      , q::frequency rate, float mix, float sps);

   float             operator()(float s);
   ...
   void              snap(); // <3>
...
private:

   q::delay          _delay; // <4>
   q::sin_cos_gen    _lfo;
   ...
   q::one_pole_lowpass _depth_slew; // <5>
   q::one_pole_lowpass _mix_slew;
};
...
inline chorus::chorus(
 ...
 : _delay{q::duration{q::as_double(base_) + q::as_double(depth_)}, sps} // <6>
   ...
   _depth_slew = _depth; // <7>
...
inline float chorus::operator()(float s)
{
   ...
   auto const d = std::clamp(
      _base + (depth * _lfo().first), 1.0f, _longest); // <8>
   auto const wet = _delay(s, d - 1.0f); // <9>
   return (s * (1.0f - mix)) + (wet * mix); // <10>
...
inline void chorus::snap()
{
...
inline void chorus::reset()
{
   _delay.clear(); // <11>
}
----
<1> Q's delay line, read at a fractional index, so the read point glides
between samples instead of stepping, and the delayed copy stays in tune
with itself as it wavers.
<2> The centre of the sweep, how far each side of it the sine reaches, how
fast, and the mix. The chorus lives in the plugin rather than in Q since
there is no one chorus: taps, waveform and feedback are an instrument's
choices.
<3> Takes the slewed settings to where they were set, at once.
<4> The line, and below it the sine that sweeps it.
<5> A step in the depth moves the read point, and a step in the mix moves
the sum, and either would be heard. Both are slewed, with the smoother
Gain uses.
<6> The line is sized once, for the centre plus the deepest sweep.
<7> Built at the settings it is given, so it starts there.
<8> The delay, in samples, swept around the centre and held inside the
line, so a setting that asks for more flattens at the edge.
<9> The line reads at its index and then takes the new sample, hence the
`- 1.0f`.
<10> The mix: 0 is the dry signal exactly, 1 the delayed copy alone.
<11> A reset clears the line and leaves the sine running.

[TIP]
====
*In depth:* {q-delay}, for the fractional delay, and {sin_cos_gen}.
====

== The Controller

Three parameters join stage 2's fourteen.

.link:{q-src}/example/q_plug/anna_3/anna_controller.cpp[anna_controller.cpp], the new parameters
[source,c++]
----
    , parameter{15, "Chorus Rate", 1_Hz}.range(0.1, 10.0).log() // <1>
    , parameter{16, "Chorus Depth", 3_ms} // <2>
         .range((0_ms).rep, (10_ms).rep).unit("s")
    , parameter{17, "Chorus Mix", 50.0}.range(0.0, 100.0).unit("%") // <3>
----
<1> A frequency, two decades on a log taper.
<2> A time, 0 to 10 ms, on a linear taper this time: it is how far the
delay sweeps each side of its centre.
<3> Dry to wet. Dry is what switching the chorus off would mean, so there
is no switch.

`anna_controller.hpp` adds the three ids, before `volume_id`, and an
accessor for each, `chorus_rate`, `chorus_depth` and `chorus_mix`, the
way stage 2 added the filter's.

== The Processor

.link:{q-src}/example/q_plug/anna_3/anna_processor.hpp[anna_processor.hpp], the synth
[source,c++]
----
   void                 update_filter();
   void                 update_chorus(); // <1>
   ...
   std::optional<chorus> // <2>
                        _chorus;       // built once the rate is known
----
<1> Pushes the chorus's settings, once per block, as `update_filter` does
the filter's.
<2> One chorus for the whole instrument, from the example's own
`chorus.hpp`. It is built in `activate`, where the sample rate is known,
hence the `std::optional`.

.link:{q-src}/example/q_plug/anna_3/anna_processor.cpp[anna_processor.cpp], activate
[source,c++]
----
   _chorus.emplace(12_ms, 10_ms, _ctl.chorus_rate(), 0.0f, float(sps())); // <1>
   update_chorus();
----
<1> Built once per activation: centred at 12 ms and able to sweep 10 ms
either side, so the line holds 22 ms. The panel's depth sweeps within
that.

.link:{q-src}/example/q_plug/anna_3/anna_processor.cpp[anna_processor.cpp], the settings
[source,c++]
----
void anna_processor::update_chorus()
{
   ...
   _chorus->rate(_ctl.chorus_rate(), rate); // <1>
   _chorus->depth(_ctl.chorus_depth(), rate);
   _chorus->mix(float(_ctl.chorus_mix()));
   ...
   if (std::ranges::none_of(_voices
    , [](voice const& v) { return v.active(); }))
      _chorus->snap(); // <2>
}
----
<1> Plain values, pushed every block like the filter's.
<2> With nothing sounding, a change takes effect at once, since there is
nothing for a glide to be heard under.

.link:{q-src}/example/q_plug/anna_3/anna_processor.cpp[anna_processor.cpp], the mix
[source,c++]
----
      auto const sum = mix * headroom * _volume(volume);
      left[frame] = right[frame] = (*_chorus)(sum); // <1>
----
<1> The chorus runs on the sum of the voices, one effect over the whole
instrument, as a pedal would be. `reset` clears its line as well.

== The Presenter

.link:{q-src}/example/q_plug/anna_3/anna_presenter.cpp[anna_presenter.cpp], the chorus
[source,c++]
----
   auto c_rate = make_slider("0.1", "0.3", "1", "3", "10"); // <1>
   auto c_depth = make_slider("0", "2.5", "5", "7.5", "10");
   auto c_mix = make_slider("0", "25", "50", "75", "100");
----
<1> Two decades of rate, so the quarters are not round numbers.

The three sliders are bound as the others are, and the chorus gets a
frame of its own beside the VCA's, in the top row. The panel stays at 816
by 504.

== The Plugin and the Build

`anna.cpp` changes the id, the name and the description.
`CMakeLists.txt` changes the names and the AudioUnit subtype, `QAn3`.
`chorus.hpp` is a header, so the build has no new source to list.

| Component              | Role

| {q-delay}             | The chorus's fractional delay line
